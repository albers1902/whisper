# Findings for Fullstack

## 1. migrate.php opdager ikke fejl i anden eller senere sætning i en migrationsfil
- Severity: Medium. Blokerende, fordi AK2 siger exit ≠ 0 ved fejl, og fundamentet bygges på inden F-numrene. 0001 har kun én sætning og er derfor ikke ramt.
- User impact: En fremtidig migration med flere sætninger kan fejle halvvejs uden at deploy stopper. Filen registreres som kørt i _migrations, og koden skiftes over et ufuldstændigt skema. På STABLE er det kundedata.
- Reproduktion: En migration 0002_...sql med `CREATE TABLE a (...); INSERT INTO findes_ikke VALUES (1);`. `$pdo->exec(file_get_contents(...))` rejser kun fejl fra første sætning. PDO MySQL kører flersætningsstrenge, men fejl i senere sætninger kommer først frem ved nextRowset(). Resultatet er exit 0 og en række i _migrations. ci.sh kører filerne med mysql-klienten, som stopper ved første fejl. CI kan derfor være grøn, mens deploy.sh ender med en halv migration.
- Exact issue: linjen `$pdo->exec((string) file_get_contents($m['path']))` i homedir/cron/migrate.php. Ingen test dækker flersætningsfiler, for AK2-testen bruger kun 0001.
- Anbefalet fix: kør filen med `$st = $pdo->query($sql); do { } while ($st->nextRowset());`. Under ERRMODE_EXCEPTION kaster nextRowset() fejl fra senere sætninger. Alternativt splittes filen i sætninger. Tilføj en test i test_H001-AK2_migrate.php: en kopi i en midlertidig mappe med en gyldig sætning efterfulgt af en ugyldig skal give exit ≠ 0 og ingen række i _migrations. Maskintjek der burde have fanget det: AK2-testen.

# Findings for Team Lead (ikke blokerende)

## 2. /health kan hænge, og hvert kald skriver i databasen
- Severity: Lav
- User impact: Ved en hængende database venter /health til PHP's timeout. deploy.sh har curl -m 20 og melder health fejlede. Endpointet er offentligt og tager en rækkelås på health_probe.id=1 ved hvert kald, så samtidige kald køer og kan time ud under belastning.
- Reproduktion: hold en åben transaktion på health_probe række 1 og kald /health flere gange.
- Exact issue: DB::pdo() sætter hverken PDO::ATTR_TIMEOUT eller kort innodb_lock_wait_timeout.
- Anbefalet fix: PDO::ATTR_TIMEOUT => 5 og eventuelt SET SESSION innodb_lock_wait_timeout=3 i probeWrite. Kan tages i en senere H-ændring.

## 3. migrate.php --status og --dry-run skriver alligevel
- Severity: Lav
- Exact issue: CREATE TABLE IF NOT EXISTS _migrations køres før --status/--dry-run-grenen, selvom kommentaren siger kør intet. Der er ingen lås mod to samtidige kørsler. En kørt migration, hvis fil er slettet, meldes ikke.
- Anbefalet fix: spring CREATE TABLE over i dry-run, advar om manglende kørte filer, og brug GET_LOCK('migrate',0).

## 4. Driftsrisiko: .htaccess kræver AllowOverride og mod_rewrite på DEV
- Severity: Lav til medium for serveropsætningen
- User impact: hvis vhosten ikke har AllowOverride FileInfo, eller serveren er nginx, giver /health 404. deploy.sh ruller så tilbage ved første udrulning.
- Anbefalet fix: sysadmin-subagenten bekræfter ved serveropsætningen, at `curl -i https://dev.whisper.xanouso.com/health` uden -L giver 200 JSON. Det skrives i SPRINT.md eller PR-teksten. .htaccess mangler også Options -Indexes, men public_html har kun health.php, så det er harmløst.
