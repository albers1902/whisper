# H009: Read-only diagnose af matchet mellem Adversus-optagelser og opkald
Type: fejl
Hvad: Ny kommando `php ~/cron/adversus-diagnose.php` (køres manuelt på DEV, ikke i crontab). Den måler, hvordan Adversus' `/calls` kan slås op for en optagelse: id-filter (`$eq` og interval), start-vinduer forskudt 0, ±1 t og ±2 t, og timestamp-filter omkring `cdr.timestamp`. Den udskriver de rå tidsstempler side om side og slutter med KONKLUSION-linjer og `DIAGNOSE: FÆRDIG`. Højst 40 Adversus-kald, kun SELECT af op til 3 rækker fra `adversus_pending`, intet skrives. Udskriver kun id'er, tidsstempler, varigheder, HTTP-status og feltnavne. `FakeAdversus` i testene kan nu afvise filter-egenskaber (HTTP 400) og tolke filtertid forskudt. Sync er uændret.
Hvorfor: F004-sync matcher næsten ingen optagelser med deres opkald (132–221 umatchede pr. vindue på DEV 2026-11-12). Swagger afgør ikke tidszone eller id-filter, så årsagen måles, før fixet laves (H009 PR 2).

Kunde: Ingen synlig ændring. Et måleværktøj til at rette hentningen af Adversus-opkald.
