## v2, finding by finding
1. **S1 (HIGH) – cron scripts ignored the flag.**
   - `zendesk-sync.php` and `transcribe.php` now exit with code 0 straight after Bootstrap if `F001_brugere` or `F002_zendesk` is off. That happens before the lock, heartbeat, database or network.
   - The Rollback line in `changes/F002.md` now says that `stable = off` (and dev/test = off) also stops fetching and transcription, and that data already fetched stays.
   - Test in AK9: with the flag off, both scripts exit 0 with no output, write nothing to the database, and create neither lock nor heartbeat. A control run with the flag on does reset the stuck call, which shows it is the flag that blocks.
   - To make that test possible, `Flags.php` (F001) can now switch a flag on through `WHISPER_TEST_FLAGS`. This only works when `WHISPER_TEST=1`, which only the test runner sets.
2. **QA F-1 – one failing ticket blocked everything.**
   - An HTTP error (status 400 or higher, except 429) on one ticket now only skips that call. The log line is `opkald <id>: springes over (HTTP 403 fra Zendesk)`.
   - 429, network errors and a rejected token still stop the run cleanly.
   - `downloadPending()` now also runs when fetching calls fails.
   - Tests in AK2: tickets returning 403 and 500 do not block the other calls, and recordings are fetched in a run where call fetching stopped.
3. **QA F-2 – calls whose VoiceComment came later were lost.** I chose the cursor lookback.
   - Every run starts 24 hours before the cursor (`Sync::LOOKBACK`).
   - A call that is already stored only gets its metadata updated, with no new comment lookups. The lookback therefore costs extra export pages, not one comments request per call.
   - Test in AK1: call 104's comment only exists on the second run, and the call is then stored.
4. **QA F-3 – a half-installed engine used up the attempts.**
   - `whisper-setup.sh` deletes `var/whisper/ready-<model>` at the start and writes it as its very last step. `available()` requires the marker for the configured model.
   - If the engine is not ready, no call is taken and no attempt is used.
   - After a failed attempt the call waits 15 minutes before the next try. This uses the new column `transcript_retry_at`, added to 0003, which has not run anywhere except CI.
   - New `cron/whisper-requeue.php` (CLI only, optional `--id=N`) sets failed calls back to waiting and resets the attempts.
   - Tests in AK4 cover: engine not ready, backoff at 0/14/16 minutes, 3 attempts, requeue including a rejected argument, and markers for the right and the wrong model.
5. **QA F-4 + S3 – zip memory.**
   - The zip route reads ids first (`Calls::zipIds`) and then transcripts 50 at a time (`zipRows`).
   - Only one zip can be built at a time (flock `zip`). Otherwise it answers 429 with `Retry-After: 30` and "Der laves allerede en zip-fil. Prøv igen om et øjeblik."
   - The `side` parameter is clamped to the last page (F-9).
   - New test file `test_F002-AK8_zip_stor.php`: 2000 transcripts of about 30 KB each, with a limit of 24 MB extra peak memory. It passed on DEV; I do not have the measured number. Also tests for the 429 lock and the clamped page.
6. **QA F-5 + S2 – stuck engine.**
   - `ProcessEngine` now polls the process. After max(2 hours, 4 × the call's duration) it sends SIGTERM, then SIGKILL after 10 seconds, and the call is marked failed with "motoren blev stoppet efter tidsgrænsen".
   - Linux test in AK4 uses a fake `python` in the venv: valid JSON is read, a process that hangs is stopped after 2 seconds, and exit code 3 gives a short error text.
7. **S4 – no access trail.** New `src/AccessLog.php` writes to `logs/adgang.log`, file mode 0600 when created:
   - `<tid> bruger=<id> lyd|transcript opkald=<id>`, and `zip antal=<n> filter=<sha256 of the filter, first 16 hex characters>`.
   - Audio is logged once per playback: the whole file or a range starting at byte 0, so seeking does not add lines.
   - Test in AK10: exact lines, and no phone numbers, names, e-mails or paths.
8. **S7 + S8 – download size and URL parsing.**
   - Downloads are capped at 500 MB, using both `CURLOPT_MAXFILESIZE_LARGE` and a progress check, which gives "optagelsen er over loftet på 500 MB".
   - `Client::hostOf()` rejects control characters, spaces and backslashes before `parse_url`.
   - Test in AK3.
9. **QA F-6 – "Venter" was shown for calls without audio.** The list now shows "Lyd mangler" or "Lyd fejlet" until the audio is fetched. "venter på transcription" only counts calls whose audio is fetched. Test in AK5.

    - F-8: a 429 is stored as "rate limit (429) — …" and shown as blue info, not a red error. Test in AK10.

## LEARNINGS
- 2026-11-11 | F002 | Cron scripts that run behind a feature flag must check the flag themselves, before lock, database and network. A flag in `features.ini` only hides the web routes, so without the check, `stable = off` is no rollback for background jobs (security S1).
- 2026-11-11 | F002 | A cron script started by a test in a new process cannot see `Flags::override`. A test-only environment flag (only when `WHISPER_TEST=1`) is needed to exercise it as a subprocess.
