## 1. Hvordan virker delsystemet ende til ende

**Request → side.**
- `homedir/src/App.php:57-169`: `handle()` → `dispatch()`. Ruten `home` kalder `CallPages::list()` (når `F002_zendesk` er
  tændt), `call_show` kalder `CallPages::show()` med flash kun i det nye UI (`Ui::modern()`, linje 152-153).
- Alle svar får CSP fra `App::csp()` (`App.php:572-581`): `default-src 'self'; style-src 'self'; img-src 'self'; …`. Der er
  ingen `font-src` og ingen `script-src`, så `default-src 'self'` gælder for fonte og scripts. Selv-hostede woff2 under
  `/assets/fonts/` er derfor tilladt uden CSP-ændring.
- `View::layout()` (`homedir/src/View.php:24-46`) sender videre til `Ui::layout()`, når `F005_ui` er tændt. Ellers er det
  det gamle UI med `legacy.css` og uden script.
- `Ui::layout()` (`homedir/src/Ui.php:34-59`) er den fælles ramme i dag: `header.top` med mærke, `nav.main-nav`, brugernavn,
  Konto og Log ud (POST med CSRF), `<main id="indhold">` og `#live`. Den linker `app.css` og `app.js` med `?v=<filemtime>`
  (`Ui::asset`, linje 62-67). Login (`UiPages::login`), konsent (`UiPages::consent`), fejl (`UiPages::error`), Konto,
  Brugere og opkaldssiderne bruger alle `Ui::layout()` (`homedir/src/UiPages.php`, `homedir/src/UiCalls.php:126,497`).
  Sektionen (`opkald|brugere|konto|''`) styrer `aria-current`. Konsent og fejlsider sender `$user`, men sektion `''`.

**Listen.**
- `CallPages::list()` (`homedir/src/CallPages.php:33-57`): `Calls::filter($req->query)` → `Calls::search($f)` (én COUNT +
  én side med 50 rækker) → med `Ui::modern()`: søgeuddrag (`Calls::snippets`, kun når `q` er sat, kun sidens id'er),
  `Calls::agents()`, `Calls::status()`, Zendesk-config, `engineReady()`, og med `Feature::on()` (F004) Adversus-config,
  -status og -advarsel → `UiCalls::list()`.
- `Calls::filter()` (`homedir/src/Calls.php:33-52`) renser `fra, til, retning, agent, q, side` og `vis` (kun `alle`, kun
  med F004). `Calls::where()` (linje 58-93) bygger WHERE med faste SQL-stykker og parametre. Kildeværnet er
  `Calls::sourceSql($vis)` (linje 100-107): uden F004 kun Zendesk; med F004 er standarden "Zendesk + Adversus-succes +
  valgte" og `vis=alle` alt.
- `CallView::query()` (`homedir/src/CallView.php:181-190`) bygger query-strengen for links (pager, chips, tilbage,
  zip). `vis` kommer kun med, når den er sat, så F004 slukket giver samme URL'er som før.
- `UiCalls::list()` (`UiCalls.php:35-129`) laver beskederne efter rolle (Zendesk/Adversus-config, sync-fejl,
  Adversus-advarsel, motor "ikke sat op"), statuslinjen (`statusLine`/`sourceLine`, linje 135-171, begge kilder under
  hinanden + "N venter på transcription · N venter på lyd"), filterformularen (`filters`, linje 192-228), segmentvælgeren
  "Succes og valgte / Alle opkald" (`viewSwitch`), chips, zip-knap, tom-tilstande og `table.calls` (linje 262-298) med
  kolonnen Kilde under F004. Pageren (linje 301-316) og `listUrl()` (linje 323-327) går gennem `CallView::query()`.

**Status og kø.**
- `Calls::status()` (`Calls.php:297-311`): Zendesk' `sync_state`-række + to COUNT: `waiting` = lyd hentet og
  (`transcriberer` eller `ventende` OG H012-reglen `QueueRules::eligibleSql`) og `audio_waiting` = lyd venter og ikke
  "ikke valgt". Begge over alle kilder (`sourceSql('alle')`). Indekserne `calls_transcript_status (transcript_status,
  started_at)` og `calls_audio_status` findes (`homedir/migrations/0003_v0.3.0_opkald.sql`).
- `QueueRules` (`homedir/src/Transcription/QueueRules.php`): `min_seconds`, `max_age_days` og `source_priority` fra
  `[whisper]`, regnes ud ved brug (ikke gemt). `skipReason()` giver badget "For kort"/"Ikke automatisk" (`Ui::status`,
  `Ui.php:102-125`). Testløberen slår reglerne fra i test-config (`homedir/tests/run.php`, `testConfig()`).

**"Transcription er ikke sat op" (AK7).**
- `CallPages::engineReady()` (`CallPages.php:352-359`) → `ProcessEngine::available()`
  (`homedir/src/Transcription/ProcessEngine.php:92-95`): `is_file(venv/bin/python) && is_executable(venv/bin/python) &&
  is_file(cron/transcribe.py) && is_file(var/whisper/ready-<model>)`.
- Motoren selv (`homedir/cron/transcribe.php`) bruger ikke `available()` til at vælge, om den kører. Den kører via cron i
  CLI og logger kun, når der er arbejde (kommentaren om advarsler: "så en tom kø ikke giver en linje hvert minut").
- Min model af den falske besked: siden kører i PHP-FPM, motoren i CLI. `venv/bin/python` er i en venv et symlink til
  systemets python (fx `/usr/bin/python3.x`). Ligger målet uden for PHP-FPM's `open_basedir`, giver `is_file`/
  `is_executable` false på web, selv om cron kører fint. `Paths.php:9` siger, at `var/` er i open_basedir, men ikke at
  `/usr/bin` er det. **Ikke målt på DEV** (se §4).

**Detaljen.**
- `CallPages::show()` (`CallPages.php:65-81`): opkald, transcript (`Calls::transcript` → `Calls::segments`, som kun beholder
  talere med `H011_diarization` tændt, `Calls.php:255-276`), lyd på disk, Zendesk-subdomæne og listens kontekst `$f`.
- `UiCalls::show()` (`UiCalls.php:345-498`): tilbage-link med `$ctx`, H1 "Indgående opkald · dato", metadata efter kilde
  (Zendesk: Ticket; Adversus: Kampagne, Lead, Succes-lead), lyd-tilstande, native `<audio id="afspiller" controls>` +
  hastighedsknapper (`data-rate`, `data-js-only`), "Transcribér dette opkald" (POST med CSRF og `ctx`), transcript-
  tilstande, søgefund (`Ui::highlight` med `<mark id="fund-1">`) og `transcript()` (linje 507-542): `<ol class="transcript">`
  med `.ts`-knapper (`data-start`) og "Agent:"/"Kunde:" ved talerskift (`Diarization::label`,
  `homedir/src/Transcription/Diarization.php:93-104`).
- `homedir/public_html/assets/app.js` (146 linjer): sætter `html.js`, viser `[data-js-only]`, tidsstempler spoler `#afspiller`,
  `is-current` på aktuel linje, hastighed, kopiér (`data-copy`, linje for linje som `[ts] tekst`), "Transcribér" én gang,
  `data-once`, bfcache-genopretning. Ingen `innerHTML`.

**Adversus-advarslen (H009).**
- `Adversus\Sync::warn()` (`homedir/src/Adversus/Sync.php:180-209`) skriver `sync_state 'adversus-warn'` og forlænger en
  advarsel, der ikke er udløbet, ved at hænge den gamle tekst foran den nye. `Calls::adversusWarning()` (`Calls.php:330-339`)
  viser den i `WARN_TTL` (86400 s, `Sync.php:80`).
- `Sync::recover()` (`Sync.php:251-270`) er H009's engangs-genopretning. Den rører ikke `adversus-warn`, så en advarsel med
  gamle id'er bliver stående, til den udløber. Forlænges den efter genopretningen, kommer de gamle id'er med igen.

## 2. Hvad rører ellers samme data, config og flow

- **MCP** (`homedir/src/Mcp/Tools.php:140,160,181,275,287`) bruger `Calls::filter`, `Calls::range` og `Calls::sourceSql`.
  Hvis jeg lægger kilde og statusfilter i `Calls::filter`/`where`, må det kun ske, når nøglerne er sat. MCP sender dem aldrig
  og skal være uændret (spec: "MCP: ingen ændring").
- **Zip** (`CallPages::zip`, linje 166-218) og "Transcribér"-redirecten (`CallPages::select`, linje 239-299) går gennem
  `Calls::filter` + `CallView::query`. Fanen og statusfilteret skal derfor med i `filter()`/`query()`, så zip og
  tilbage-redirecten bevarer dem (AK2, AK10). `select()` renser `ctx` gennem `filter()` igen, og det skal stadig gælde.
- **Det gamle UI** (`CallView`, `View`) og **F005 uden F007** bruger de samme `Calls`-funktioner. Med `F007_kilder` slukket må
  `filter()` ikke returnere nye nøgler med værdi, og `query()` må ikke give nye parametre (AK8).
- **Flag-afhængigheder**: `F005_ui` (Ui::modern), `F004_adversus` (`Adversus\Feature::on()`), `H011_diarization`
  (`DiarizationSettings::FLAG` i `Calls::segments`), `F003_mcp` (Claude-boksen), `F006_oauth`. UI/UX v2 §0: F007 kræver
  F005; med F004 slukket er der ingen faner.
- **Eksisterende tests, der låser F005's ramme**: `homedir/tests/test_F005-AK1_ingen_inline.php` kræver bl.a.
  `<link rel="stylesheet" href="/assets/app.css?v=…">`, app.js under 150 linjer og ingen `url(` i app.css. F004-, F005- og
  H011-testene kører med `env = test`, hvor `F007_kilder` er off, så de dækker flag-off-vejen.
- **Transcription-motoren** (`cron/transcribe.php`, `Transcriber`) læser `calls` og skriver status. UI'et må kun læse.
  Ejerens krav (MEMORY: "Ingen GPU, kun CPU") er, at intet bliver langsommere.

## 4. Hvad ved jeg ikke

1. **Hvorfor `engineReady()` er false på DEV.** Min hypotese er open_basedir + symlink til python. Jeg har ikke målt det.
   Plan uanset årsag (spec: "læses fra den samme kilde som motoren"): kø-kortets status bygges af `var/whisper/ready-<model>`
   (sat op/ikke sat op) og `logs/transcribe.log`'s mtime (seneste aktivitet) + om et opkald står i `transcriberer`. Python-
   tjekket fjernes fra sidens status (ikke fra motoren). Kan markøren ikke læses (fx open_basedir på `var/`), vises
   "Ukendt status", aldrig "Ikke sat op" på et gæt (UI/UX v2 §3). Spørgsmål til Team Lead: skal sysadmin bekræfte
   open_basedir på DEV, før jeg retter, eller er spec'ens regel nok?
2. **Byte-identisk med flaget slukket (AK8).** Der er ingen lokal database (kun PHP 8.2 lokalt). Plan: renderfunktionerne
   (`UiCalls::list/show`, `UiPages::*`, `Ui::layout`) er rene funktioner af arrays. Jeg laver snapshots af deres output fra
   main @ 3c0be86 lokalt (faste fixtures, normaliseret `?v=`) og en test, der sammenligner byte for byte med flaget slukket.
   Dertil DB-tests på DEV for controllerne (`Calls::filter`, `CallView::query`, SQL) med flaget slukket.
3. **Ydelse af uddrag med talere.** `segments_json` er MEDIUMTEXT. 50 fulde JSON'er kan være flere MB. Plan: ét SELECT med
   `LEFT(segments_json, ~3000)` og `LEFT(text, ~260)` for sidens id'er, kun når `q` er tom, og en afkortet JSON repareres
   ved sidste hele `}` (ellers faldes tilbage til teksten). Ikke målt på DEV-data.
4. **Kø-kortet på alle sider** koster `Calls::status()` (2 COUNT + 1 lille SELECT) på Konto og Brugere også. Jeg tror, det er
   billigt med de eksisterende indekser, men har ikke målt det.
5. **Fonte.** Visuelt brief v2 siger `@fontsource/inter` og `@fontsource/inter-tight` (latin-subset), Team Lead nævner
   rsms/inter-releases eller google/fonts. Plan: npm-registry-tarballs for `@fontsource/inter` og `@fontsource/inter-tight`
   (5.x), verificeret mod registry'ets `dist.integrity` (sha512), filerne `files/*-latin-*-normal.woff2` + LICENSE. Kilde,
   version og sha256 pr. fil skrives i rapporten. Sig til, hvis du kræver rsms/inter i stedet (den har ikke Inter Tight).
6. **Servering af woff2.** `homedir/public_html/.htaccess` er ikke læst endnu. Om Apache sender `font/woff2` og lang cache
   tjekkes i implementeringen.
7. **app.js' 150-linjers-grænse** (`test_F005-AK1`). Ny JS (menu, afspiller, find i samtalen, piller) lægges i en ny
   `app-v2.js`, der kun linkes med flaget tændt sammen med `app-v2.css`. Med flaget tændt indlæses kun v2-filerne. Så er
   F005-filerne og -testene uændrede.
