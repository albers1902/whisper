# System understanding

H005 — hurtigere transcription og måling (RTF i loggen). Tier 2, Type: fejl.

## 1. Hvordan delsystemet virker ende til ende
- `homedir/cron/transcribe.php` (cron hvert minut, lås `transcribe`) bygger `ProcessEngine::fromConfig()` og kører
  `Transcriber::runOnce()` i løkke i højst 50 min. Kilde: `homedir/cron/transcribe.php` (læst hele filen).
- `homedir/src/Transcription/ProcessEngine.php` starter motoren med `proc_open($argv, …)` og et argv-array:
  `nice -n 19 [ionice -c3] var/whisper/venv/bin/python cron/transcribe.py --model <m> --models <dir> <fil>`.
  Ingen shell. Model kun fra `MODELS`. Tidsgrænse `max(7200, 4 × varighed)`. Kilde: samme fil (læst hele).
- `homedir/cron/transcribe.py` kalder `WhisperModel(model, device="cpu", compute_type="int8", download_root=…)` og
  `model.transcribe(audio, language="da")`. Ingen threads, beam eller VAD, så faster-whispers standarder gælder.
  Svaret har også `duration` (fra `info.duration`). Kilde: `homedir/cron/transcribe.py` (læst hele).
- `homedir/src/Transcription/Transcriber.php` logger i dag `transcribe: opkald <id>: færdig` uden tal. Den har en
  injicerbar `clock` (int-sekunder) og `log`. Kilde: samme fil (læst hele).
- Config læses af `homedir/src/Config.php` med `INI_SCANNER_RAW`, så alle værdier er strenge. `[whisper] model`
  er den eneste nøgle i dag. Kilde: `homedir/src/Config.php` og `ProcessEngine::fromConfig()`.

## 2. Parametre i faster-whisper 1.2.1 (kilde)
Versionen er låst i `homedir/cron/whisper-requirements.txt` (`faster-whisper==1.2.1`, `onnxruntime==1.31.1`).
Læst i `faster_whisper/transcribe.py` og `faster_whisper/vad.py` på tag `v1.2.1` (github.com/SYSTRAN/faster-whisper):
- `WhisperModel.__init__(…, device="auto", device_index=0, compute_type="default", cpu_threads: int = 0, num_workers: int = 1, …)`.
  `cpu_threads=0` overlader det til CTranslate2, som bruger 4 tråde på CPU (spec'ens måling).
- `WhisperModel.transcribe(…, beam_size: int = 5, …, vad_filter: bool = False, vad_parameters=None, …)`.
  Med `vad_filter=True` (og `clip_timestamps="0"`) bruges `VadOptions()` og `get_speech_timestamps(audio, …)`.
- `vad.py`: `get_vad_model()` (lru_cache) loader `assets/silero_vad_v6.onnx` via `get_assets_path()` og
  `import onnxruntime` i `SileroVADModel.__init__`; mangler pakken, kommer `RuntimeError("Applying the VAD filter
  requires the onnxruntime package")`. Intet hentes under kørslen. onnxruntime står allerede i låsefilen (H003),
  så VAD virker offline (`HF_HUB_OFFLINE=1` er uændret).
- Navnene er altså `cpu_threads`, `beam_size` og `vad_filter`.

## 3. Antal kerner i PHP uden shell
Primært `/proc/cpuinfo` (antal linjer `processor : N`), ellers `/sys/devices/system/cpu/online` (fx `0-5`).
Begge læses med `is_readable` + `file_get_contents`, ingen proces. Kan ingen af dem læses (fx Windows eller
open_basedir), bruges 4 tråde, som er faster-whispers adfærd i dag. Jobbet kører som CLI-cron
(`transcribe.php`), hvor FPM-poolens open_basedir ikke gælder (LEARNINGS F001 handler om web).

## 4. Hvad ellers rører samme data
- `homedir/tests/test_F002-AK4_transcription.php` bruger en falsk `python` i venv'et og tjekker, at loglinjerne
  matcher `^transcribe: opkald [0-9]+: `. Det nye format bevarer præfikset.
- `FakeEngine` i `homedir/tests/f002_lib.php` implementerer `Engine`. Udvides interfacet, skal den følge med.
- `transcripts`-tabellen og `model` ændres ikke.

## 5. Plan
- `transcribe.py`: `--threads` (1–32), `--beam` (1–10), `--vad 0|1` med argparse-typer. Ugyldige værdier giver exit 2
  før import af faster_whisper.
- Ny `WhisperSettings` (threads, beam, vad) med `fromSection(array, ?int $cores, warn)`. Standarder er kerner−1
  (mindst 1), beam 1 og vad on. Ugyldige værdier giver standarden og én advarsel pr. nøgle.
- `ProcessEngine` tilføjer `--threads N --beam N --vad 0|1` som argv-elementer. `nice`/`ionice` er uændrede.
- `Engine::label()` giver `threads 5, beam 1, vad on`. `Transcriber` måler tiden og logger
  `opkald 120: færdig (lyd 4:12, tid 1:05, RTF 0,26, threads 5, beam 1, vad on)`.

## 6. Hvad jeg ikke ved
- Om `silero_vad_v6.onnx` ligger i wheel'en til 1.2.1. Det tror jeg (assets er package_data), men det er ikke
  målt på DEV. Fejler VAD, fejler opkaldet med exit ≠ 0 og kan slås fra med `vad = off`.
- Den reelle RTF-gevinst. Den måles med den nye loglinje.
