## What is built
- **Zendesk.** Metadata comes from the Talk Incremental Export. `recording_url` comes from the ticket's VoiceComment, matched on `data.call_id`, otherwise on start time ±2 min and duration ±5 s. Calls without a recording are not stored.
- **OAuth.** Uses client_credentials (JSON body), with an empty scope or a write scope rejected (default `read`). The token cache is `var/zendesk-token.json`, mode 0600, and holds neither the client id nor the secret. The token is renewed 60 s before it expires, and once on a 401.
- **429.** If `Retry-After` is 60 s or less, it waits and retries, at most 3 calls in total. A longer wait stops the run cleanly.
- **Cursor and idempotency.** The cursor (`end_time`) is only saved after a whole page has been stored. Re-runs are idempotent through an UPSERT on `(source, external_id)`.
- **Recordings.**
  - Saved to `var/recordings/ÅÅÅÅ/MM/<id>.mp3|wav` with mode 0600, via a `.part` file. At most 5 attempts.
  - Redirects are followed by our own code. Authorization is only sent to `<sub>.zendesk.com`. Any other host is only allowed if it is listed in the new config key `[zendesk] recording_hosts`.
- **Transcription.**
  - Model `turbo` or `large-v3`, run with argv only (no shell) under `nice` (and `ionice` only if it exists).
  - It runs with `HF_HUB_OFFLINE=1`, so no network calls during transcription.
  - Claiming a call is one atomic UPDATE. A call stuck over 2 hours is only reset by the run that holds the flock. At most 3 attempts.
  - It reconnects to the database after a long run (`DB::ensureAlive`).
- **UI.**
  - `/`: call list with filters (danish dates, direction, agent, free text via FULLTEXT BOOLEAN or LIKE for words under 3 characters). Empty states and a sync status line.
  - `/opkald/{id}`: the call page.
  - `/opkald/{id}/lyd`: audio with Range support and `Cache-Control: private, no-store`.
  - `/opkald/{id}/transcript`: the .txt file.
  - `/opkald/download`: zip written in pure PHP, at most 2000 files.
