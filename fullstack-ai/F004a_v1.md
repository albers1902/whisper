## System understanding: holdt
v0 (`fullstack-ai/F004a_v0.md`, commit fe9d716) holdt, også konklusionen om, at API'et kan levere optagelser. Kilde: Adversus' officielle API-spec `https://api.adversus.io/swagger/apinew.json` (Swagger 2.0, v1.2.1), som Redoc-siden `https://solutions.adversus.io/api` indlæser.
- Auth: HTTP Basic med en API-bruger. Base: `https://api.adversus.io/v1`.
- Endpoints: `/organization`, `/calls`, `/calls/{id}/recording` (307 til en URL, der gælder i højst 2 t), `/recordings` (Adversus anbefaler den til eksport), `/sessions`, `/campaigns`, `/leads`.
- Sideinddeling: `page`/`pageSize` (1–100) og `includeMeta=true`, som giver `meta.pagination`.
- Rate limits: 1000/time, 60/min, højst 2 samtidige. Over grænsen svarer API'et 429; `Retry-After` er ikke dokumenteret.
- `/calls` har intet felt for optagelse og hverken `/calls/{id}` eller et id-filter. "Opkald med optagelse" tælles ved at matche `cdr.id` fra `/recordings` mod de skannede opkald.

## Hvad er lavet
- `AdversusConfig`: læser `[adversus]` med `username`, `password`, `since` og valgfri `recording_hosts`. Fejlbeskeder nævner aldrig værdier, og kolon i brugernavnet afvises (RFC 7617).
- `Client`: Basic auth kun til `api.adversus.io`; 429 med `Retry-After` (60 s hvis den mangler), højst 60 s og 3 forsøg; `downloadRecording()` følger redirects manuelt (højst 5) med værttjek, Authorization aldrig til andre værter, kun https/443 uden brugerinfo; `errorText()` renser hemmeligheder (også base64), e-mails, URL'er, navngivne felter, Basic/Bearer og token-lignende ord, højst 200 tegn.
- `Probe::run(...)`: kun feltnavne der ligner feltnavne, enum-værdier kun fra dokumentationens lister ("(andet)" ellers), optagelsen hentes til `var/tmp` og slettes i `finally`.
- `cron/adversus-probe.php`: kun CLI, tjekker curl og kalder `Probe::run`.
- Genbrug af F002's `HttpTransport`, `CurlTransport`, `HttpResult` og `Zendesk\Client::hostOf()` uændret.

## Afvigelser fra spec
1. Enum-værdier er en whitelist fra Adversus' dokumentation i stedet for regex'en `[a-z_]{1,40}` (Adversus bruger `no-answer` og camelCase).
2. `--call` leder efter id'et i ≤ 5 sider fra `since`, fordi API'et ikke har `/calls/{id}`, og henter så optagelsen via `/calls/{id}/recording`.
3. Ved rate limit stopper proben med exit 1, men skriver stadig `PROBE: FÆRDIG`.

## Hvad ejeren skal gøre
**I Adversus** (kilde: help.adversus.io/en/articles/5781-create-an-api-user):
1. Log ind som admin, eller med rettigheden "User administrations" eller "API access administration".
2. Gå til **Users → Create → Create API access**.
3. Skriv et User name, fx `whisper-probe`, og vælg Access type **Readonly**. Alternativ: **Custom** med læseadgang til organization, calls, recordings, sessions, campaigns og leads.
4. Klik **Create API access**. Adgangskoden vises kun her.

**På DEV:** `vi ~/config/config.ini` og tilføj:
```
[adversus]
username = <API-brugernavn>
password = <API-adgangskode>
since = 2026-10-01
```

**Probe-kommandoer:**
- `php ~/cron/adversus-probe.php`
- Står der `(ikke godkendt)` ved en vært i optagelsens kæde: tilføj `recording_hosts = <den vært>` under `[adversus]` og kør igen.
- `php ~/cron/adversus-probe.php --call=<opkalds-id>` for et kendt optaget opkald.
