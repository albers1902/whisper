# System understanding

F005 — nyt UI (redesign) · branch `feature/F005-ui` · spec `product-ai/F005_v1.md` · impact `tasks/impact-F005.md` ·
ingen migration · flag `[F005_ui]`. Skrevet 2026-11-11, før kode. Briefs: `ui-ux/F005_design_v1.md`,
`graphic-design/F005_visual_v1.md`.

## 1. Hvordan delsystemet virker i dag (læst)
- `homedir/public_html/index.php` → `homedir/src/App.php` `handle()`: F001-flag først, rute, login, CSRF, controller.
  `App::secure()` lægger CSP `default-src 'self'; style-src 'self'; img-src 'self'` (script-src falder til `'self'`)
  på alle svar — derfor ingen inline script/style.
- `homedir/src/View.php`: alle sider er PHP-strenge. `View::layout($title, $body, $user, $csrf)` er den fælles ramme
  (header, nav, `<link href="/assets/app.css">`). Sidefunktioner: `login`, `home`, `account` (+ privat `mcpSection`,
  F003), `users`, `userNew`, `oneTimePassword`, `userEdit`, `confirm`, `error`; hjælpere `e`, `csrfField`, `message`,
  `dateTime`, `mcpConfig`.
- `homedir/src/CallView.php`: `list` (filtre, statuslinje, beskeder, tabel, pager, zip) og `show` (meta, lyd,
  transcript), `badge` (privat), `query`. Kaldes kun fra `homedir/src/CallPages.php` (`list`, `show`); `zip` bruger
  `View::layout` direkte.
- `homedir/src/CallPages.php::list` bygger `notices` som færdige strenge (config mangler/ugyldig, motor ikke klar);
  `show($id, $user, $csrf)` får ikke requesten, så listens query kan ikke nå detaljen i dag.
- `homedir/src/Calls.php`: `filter()` renser query (`fra, til, retning, agent, q, side`), `where()` tokeniserer `q`
  med `/[\p{L}\p{N}]+/u` (ord ≥ 3 tegn → FULLTEXT `+ord*`, ellers LIKE), `search()` henter `c.*` for 50 rækker
  (ingen transcript-tekst). `transcripts.text` er MEDIUMTEXT, `utf8mb4_unicode_ci`
  (`homedir/migrations/0003_v0.3.0_opkald.sql`).
- `homedir/public_html/.htaccess`: filer under `assets/` serveres direkte (RewriteCond `!-f`).

## 2. Hvordan flaget holder det gamle UI intakt
- Ny `Ui::modern()` = `Flags::enabled('F005_ui')`. Hver offentlig sidefunktion i `View` får som FØRSTE linje
  `if (Ui::modern()) { return UiPages::<samme>(…); }`. Resten af funktionen er byte-uændret.
- `CallView` røres ikke. `CallPages::list/show` vælger `UiCalls` eller `CallView` som det første efter dataopslag;
  `show` får `Request` med (App ændres på én linje), så query'en kan bæres videre. Den gamle gren ignorerer den.
- CSS: den nuværende `app.css` kopieres byte-uændret til `assets/legacy.css`, og den gamle `View::layout` linker til
  den (eneste ændring i gammelt output: filnavnet). `app.css` bliver den nye efter det visuelle brief, og `app.js`
  er ny. Det nye layout linker begge med `?v=<filemtime>` (KAN 26).
- `View::layout` får en valgfri `$section` (`opkald|brugere|konto|''`), som kun det nye layout bruger.
- Nye filer: `src/Ui.php` (layout, ikoner, badge, beskeder, fremhævning, uddrag), `src/UiPages.php` (login, konto
  inkl. MCP, brugere, fejl), `src/UiCalls.php` (liste, detalje). `Calls.php` får kun `snippets(ids, q)`.
- Eksisterende tests kører med `env = test` (flag off) og rammer derfor det gamle UI uændret.

## 3. Hvad er prøvet før (LEARNINGS, critic-reviews)
- `security-critic/F003_v1.md`: `get_transcript` begrænser tekst med `LEFT(…, ?)` i SQL. Uddrag gør det samme:
  `SUBSTRING(t.text, GREATEST(1, LOCATE(?, t.text) - 120), 480)` for højst 50 id'er — aldrig hele teksten i PHP.
- `qa-critic/F002_v2.md` F-4: hukommelsen må ikke vokse med antallet (zip i batches); samme princip her.
- Fremhævning: tokenisér den RÅ tekst (`preg_split` med delim-capture), escape hvert token og pak kun ord-tokens i
  `<mark>`. Der søges aldrig i escaped HTML (UX §3.4, D6).

## 4. Hvad jeg ikke ved
- `LOCATE` under `utf8mb4_unicode_ci` er accent-ufølsom (`maler` finder `måler`), mens PHP-fremhævningen er
  præfiks på `mb_strtolower`. Et uddrag kan derfor stå uden `<mark>`, hvis kun en accentvariant matchede. Uddraget
  vises så alligevel (ingen fejl). Ændrer ikke spec'en.
- Responsivt 700–1099px: `dl.meta` renderes to gange (i venstre kolonne og i `<details>` under transcriptet), og CSS
  skjuler den ene efter bredde. Ingen JS.
- Om DEV's `config.ini` har `[app] env = dev` (kræves for alle flag; F001-learning) — det har den, siden F001–F003 kører.

Ingen af punkterne ændrer spec'en; jeg fortsætter med koden.
