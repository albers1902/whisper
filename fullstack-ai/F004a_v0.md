# System understanding

## 1. Hvordan virker delsystemet ende til ende?

### Adversus' API (officiel kilde)
Kilde: `https://solutions.adversus.io/api` (Adversus' API-dokumentation, en Redoc-side) indlæser spec'en
`https://api.adversus.io/swagger/apinew.json` (Swagger 2.0, "Adversus API v1 docs", version 1.2.1), hentet og læst
2026-11-12. Alle påstande herunder er fra den fil, medmindre andet står.

- **Auth:** `securityDefinitions.basicAuth = {type: basic}` — HTTP Basic auth på alle endpoints, med en API-brugers
  brugernavn og adgangskode. Ingen tokens, ingen OAuth. Et kald uden login til `https://api.adversus.io/` gav
  HTTP 401 (målt 2026-11-12).
- **Base-URL:** `host: api.adversus.io`, `basePath: /v1`, `schemes: [https]` → `https://api.adversus.io/v1`.
  (Pipedreams tredjepartsside bruger `api.adversus.dk/v1`; den officielle spec siger `.io`, og vi bruger kun den.)
- **Sideinddeling:** `page` og `pageSize` (1–100; "Default is 1000"). Med `includeMeta=true` kommer
  `meta.pagination` med `page`, `pageCount`, `pageSize`, `total`, `firstUrl`, `previousUrl`, `nextUrl`, `lastUrl`.
- **Filtre:** `filters=<JSON>` med `$eq`, `$gt`, `$lt`, `$c`, `$nc`, `$neq`; flere på samme felt er tilladt, fx
  `{"start":{"$gt":"2026-10-01T00:00:00Z"}}`. Sortering: `sortProperty` + `sortDirection` (`ASC`|`DESC`).
- **Rate limits:** "1000 requests pr. hour, with a burst rate limit of 60 requests pr. minute, and a maximum of 2
  concurrent requests. If the rate limit is exceeded the API will respond with a 429 status code." `Retry-After`
  er ikke dokumenteret.
- **Fejlformat:** definitionen `error` = `{code: int, message: string}`.
- **Relevante endpoints (alle GET, alle basicAuth):**
  - `/organization` — id og navn på API-brugerens organisation. Bruges som auth-tjek.
  - `/calls` — "List call detail records". Felter (`call-entry`): `id`, `campaignId`, `leadId`, `contactId`,
    `userId`, `disposition` (enum `answered|busy|no-answer|failed|congestion`), `byeCause`, `start`, `answer`,
    `connect`, `end`, `number`, `extension`, `duration`, `queued`, `billable`, `dialing`, `conversation`, `sip`,
    `origin` (enum `inbound|outbound`), `anonymous`. Filtre: `campaignId`, `userId`, `start`, `timestamp`.
    Sortering: `timestamp`, `start`. Svar: `{"calls": [...]}` (+ `meta`). Intet felt siger, om opkaldet har en
    optagelse, og der er ingen `/calls/{id}` og intet `id`-filter.
  - `/calls/{id}/recording` — "Get download link for recorded audio": svarer **307** "HTTP redirect to the
    recording download URL. The returned location is valid for no longer than 2 hours"; 404 = opkald eller
    optagelse findes ikke. `id` er `integer`.
  - `/recordings` — "Returns recordings and recording-clips ordered by, and optionally filtered by upload time.
    This is the recommended way to export recordings to a media archive." Filter `timestamp`. Hvert element:
    `cdr.id` (opkaldets id), `cdr.timestamp`, `recording.name`, `recording.download` ("Temporary url … may be null if
    operation is not allowed"), `clips[]` (`id`, `tagId`, `download`), `timestamp` (upload-tid, cursor).
  - `/recording-clips` — kun klip (dele markeret af agenten). Ikke relevant for hele samtaler.
  - `/sessions` — sessioner (et opkaldsforløb på et lead): `id`, `leadId`, `userId`, `campaignId`, `startTime`,
    `endTime`, `lastUpdatedTime`, `status` (`new, automaticRedial, privateRedial, notInterested, success, invalid,
    unqualified, unknown`), `sessionSeconds`, `cdr{destination, startTime, answerTime, endTime, durationSeconds,
    disposition}`. Filtre: `id`, `leadId`, `userId`, `campaignId`, `startTime`, `endTime`, `lastUpdatedTime`,
    `status`. Svaret er i spec'en et array; beskrivelsens eksempel viser `{"meta": …, "sessions": [...]}` med
    `includeMeta`. Begge former håndteres.
  - `/campaigns`, `/leads` — lister; kun feltnavne og antal på første side er interessante for F004.
  - `/cdr` og `/cdr/{id}/recording` er markeret "deprecated — use GET /calls" og bruges ikke.
- **Den mest direkte vej til "opkald med optagelse":** `/recordings` (filtreret på upload-tid) giver opkaldenes id
  (`cdr.id`) for alle optagelser; `/calls/{id}/recording` giver lyden via en 307 til en tidsbegrænset URL. Opkaldets
  tal (varighed, retning, disposition) står i `/calls`. **API'et kan altså levere optagelser** → jeg fortsætter.

### Oprettelse af API-bruger i Adversus
Kilde: `https://help.adversus.io/en/articles/5781-create-an-api-user` (læst 2026-11-12): kræver admin eller
rettighederne "User administrations"/"API access administration". **Users → Create → Create API access**, skriv et
**User name**, vælg **Access type**, klik **Create API access** — adgangskoden vises da (én gang). Access types:
**Admin** (læs og skriv på alle routes), **Readonly** ("Can access the routes, but only read data"), **Custom**
(udvalgte routes, kampagner og lead pools). Til proben: **Readonly** (eller Custom med kun læsning af
organization, calls, recordings, sessions, campaigns, leads). Ændres under Users → fanen API accesses
(`.../5790-edit-an-api-user`).

### Mønsteret fra F002/H002, der genbruges
- `homedir/src/Zendesk/HttpTransport.php`, `HttpResult.php`, `CurlTransport.php` (læst): ét HTTP-kald, kun https,
  `CURLOPT_FOLLOWLOCATION => false`, certifikattjek, loft på 500 MB ved download, netværksfejl som kort tekst med
  curl-fejlnummer (aldrig URL). Interfacet er generisk; fejlene er `ZendeskError`. Jeg genbruger de tre klasser
  uændret og oversætter `ZendeskError` fra transporten til `AdversusError` i Adversus-klienten.
- `homedir/src/Zendesk/Client.php` (læst): `download()` følger redirects selv (højst 5), tjekker værten for hvert hop,
  sender `Authorization` kun til egen vært, gemmer statuskæden som `[host, status]` i `lastChain`. `hostOf()` afviser
  andet end https/443 uden brugerinfo og kontroltegn. `retry429()`: `Retry-After` højst 60 s, højst 3 forsøg, ellers
  `RateLimited`. `oauthErrorText()`: fjerner kendte hemmeligheder, navngivne felter, `Bearer/Basic …` og
  token-lignende ord, kun printbar ASCII, højst 200 tegn. Samme mønstre bygges i `Adversus\Client` (Basic auth i
  stedet for Bearer, `{code,message}` i stedet for `{error,error_description}`).
- `homedir/src/Zendesk/Probe.php` (læst): `numbers()` viser kun tal og enum-værdier `[a-z_]{1,40}`, `keys()` kun
  sorterede feltnavne, `tryDownload()` henter til `var/tmp/probe-<rnd>.part` og sletter i `finally`, udskriver
  Content-Type renset og størrelse og kæden af værter.
- `homedir/cron/zendesk-probe.php` (læst): `PHP_SAPI !== 'cli'` → 404/exit 2; argumenter valideret med regex,
  ukendte afvises med exit 2; sidste linje `PROBE: FÆRDIG`.
- `homedir/src/Zendesk/ZendeskConfig.php` (læst): sektionen læses fra config.ini, beskeder nævner aldrig værdier,
  `recording_hosts` valideres som værtsnavne.

## 2. Hvad rører ellers samme data?
- Intet: proben skriver ikke i databasen, har ingen cache og intet UI. `Config::section()`
  (`homedir/src/Config.php`) giver `[]`, når `[adversus]` mangler. `Paths::dir('tmp')` (`homedir/src/Paths.php`)
  giver `var/tmp` (0700) til den midlertidige lydfil, samme sted som Zendesk-proben.
- Testene kører uden netværk (`homedir/tests/run.php` peger proxies på en lukket port) og mocker HTTP med
  `FakeTransport` fra `homedir/tests/f002_lib.php`; jeg genbruger den.
- F004 (senere) bygger hentningen på det, proben viser. DECISIONS (`launched/STABLE/DECISIONS.md` linje 6) siger
  rækkefølgen: Zendesk, MCP, så Adversus.

## 3. Hvad er prøvet før?

## 4. Hvad ved jeg ikke?
- **Hvilken vært 307'eren peger på** (fx en S3-/CDN-vært). Proben stopper ved første ukendte vært og viser kun
  værtsnavnet med "ikke godkendt"; ejeren skriver den i `[adversus] recording_hosts` og kører igen (som F002).
- Om **Readonly** giver adgang til `/recordings` og `/calls/{id}/recording` (`download` "may be null if operation is
  not allowed"). Proben viser HTTP-status pr. endpoint og antal `download`=null.
- Om `/calls` overhovedet har opkald for TrygEnergi (kun opkald via Adversus' dialer) — vises som antal.
- Lydformat og størrelse (Content-Type) — måles.
- Om 429-svar har `Retry-After` (ikke dokumenteret). Uden headeren venter klienten 60 s (burst-grænsen er pr.
  minut), højst 3 forsøg; ellers stopper proben pænt.
- Om `/sessions` svarer med et array eller et objekt med `sessions` — begge håndteres.
- Om Adversus' fejl-`message` kan indeholde brugernavnet — den renses uanset.
