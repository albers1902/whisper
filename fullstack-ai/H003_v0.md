# System understanding

## 1. Hvordan virker delsystemet ende til ende?
- `homedir/cron/whisper-setup.sh` (læst hele filen): læser `[whisper] model` fra `config/config.ini` (turbo|large-v3),
  fjerner `var/whisper/ready-<model>`, opretter `var/whisper/venv` hvis `bin/python` mangler, og kører
  `pip install -q "faster-whisper==1.1.1"` uden låsning af transitive pakker. Derefter et heredoc med
  `WhisperModel(model, device="cpu", compute_type="int8", download_root=var/whisper/models)` med `HF_HOME=var/whisper/hf`,
  og til sidst markøren `ready-<model>`. Der er intet import-tjek før modelhentningen.
- `homedir/src/Transcription/ProcessEngine.php` (linje 11, 42, 47, 87–89): transcription kører
  `var/whisper/venv/bin/python cron/transcribe.py --model <m> --models var/whisper/models <fil>` med `HF_HUB_OFFLINE=1`,
  og kun når `ready-<model>` findes.
- `homedir/cron/transcribe.py` (læst hele filen): `WhisperModel(a.model, device="cpu", compute_type="int8",
  download_root=a.models)` og `model.transcribe(audio, language="da")`. Ingen `revision`.
- **Fejlens årsag (læst i wheel'en):** `faster_whisper-1.1.1-py3-none-any.whl` `faster_whisper/utils.py` linje 8 er
  `import requests`, men 1.1.1's METADATA kræver ikke `requests` (det kom tidligere med `huggingface_hub` 0.x). PyPI har
  nu `huggingface-hub` 2.4.0 (requires_dist: `httpx2`, ingen `requests`), så pip vælger den, og importen fejler.
- **faster-whisper 1.2.1** (PyPI 2025-10-31, nyeste): `utils.py` importerer ikke længere `requests` (release-noten
  "Offload retry logic to hf hub", PR #1382). Men `download_model()` sender stadig `local_dir_use_symlinks` når
  `output_dir` er sat, og `huggingface_hub` 1.0.0's `snapshot_download` har ikke den parameter (læst i begge wheels;
  0.36.2 har den). Vi bruger `download_root` = `cache_dir`, ikke `output_dir`, men låsen holder
  `huggingface-hub==0.36.2` (sidste 0.x, 2026-02-06) for at blive på den API, faster-whisper er skrevet til.
  `huggingface-hub` 0.36.2 kræver selv `requests`, så AK3 er opfyldt begge veje.
- 1.2.1 understøtter `turbo` (`_MODELS["turbo"] = "mobiuslabsgmbh/faster-whisper-large-v3-turbo"`) og `WhisperModel`
  har `revision=` (release 1.2.0, PR #1292). `transcribe.py`'s brug er uændret i 1.2.1 (samme signatur).

## 2. Hvad rører ellers samme data?
- `ProcessEngine.php` læser venv'ets python og markøren; `transcribe.py` læser modellen offline fra HF-cachen i
  `var/whisper/models` (`download_root` → `cache_dir`, så `refs/main` skal pege på snapshot'et).
- Konsekvens for revision-låsning: henter setup med `revision=<sha>`, skriver huggingface_hub ikke `refs/main`, og
  `transcribe.py` (uden revision, offline) finder så ikke modellen. Derfor låser setup revisionen ved at hente `main`
  og afvise (ingen markør), hvis snapshot'ets sha ikke er den låste. `transcribe.py` røres ikke (out of scope).
