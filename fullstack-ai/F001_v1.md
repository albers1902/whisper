## System understanding
v0 held. Its four open points are settled as you answered:
- Environment comes from `config.ini [app] env`, normalised `development`→`dev` and `production`→`stable`. Missing or unknown means off.
- Sessions are in `var/sessions`, created with 0700 if missing.
- Only `REMOTE_ADDR` is used for the client IP.
- The app cleans up its own sessions: `gc_maxlifetime` 8 h with GC probability 1/100, and the timeout is also enforced in code.

## What was built
- **Routing:** front controller `public_html/index.php` → `App::handle(Request, Session): Response`. The flag is checked before the session starts.
- **`.htaccess`:** the `/health` rule is unchanged and comes first. After it, a catch-all with `!-f` sends everything else to `index.php`.
- **Login and logout:** e-mail is trimmed and lower-cased. The session id is renewed at login, and logout destroys the session completely. Inactivity timeout is 8 hours.
- **Session cookie:** `whisper_session`, always `Secure`, `HttpOnly`, `SameSite=Lax`, with `use_strict_mode`.
- **Checked against the database on every request:**
  - role and active status;
  - a fingerprint of the password hash, so a reset or password change logs out the user's other open sessions.
- **CSRF:** one token per session, compared with `hash_equals`. Every POST without a valid token gets 403 and changes nothing. A POST with an expired session redirects to `/login`.
- **Throttling:** 5 failed attempts within 15 min for the same e-mail or the same IP lock for 15 min from the fifth attempt. Rejected attempts during the lock are not counted, so the lock always ends on time. Rows older than 30 days are deleted at login.
- **`/brugere`:** list, create (16-character one-time password from `random_bytes`, shown once, `must_change_password`), edit name and role, reset password, deactivate and reactivate.
- **Last-admin rule:** checked in a transaction with `SELECT … FOR UPDATE` on the active admins and the target user. An admin cannot deactivate themselves.
- **`/konto`:** change own password. It requires the current password, at least 12 characters, a matching repeat, and a password different from the current one. A forced change locks out all other pages until it is done.
- **`cron/opret-admin.php`:**
  - only runs from CLI;
  - reads the password from stdin, without echo and with a repeat prompt on a terminal;
  - refuses unknown arguments (so a password cannot be passed as `--password=`) and refuses an e-mail that already exists;
  - exits with ≠ 0 on any error.
- **Security headers on every app response:** CSP without inline code, `X-Frame-Options DENY`, `nosniff`, `Referrer-Policy same-origin`, `Cache-Control no-store`.
- **HTML and CSS:** all output goes through `htmlspecialchars`. Plain Danish HTML in `View.php`, CSS in `assets/app.css`, no JS and no CDN.

## Deviations from the spec
1. There are no template files in `src/templates/`. The pages are typed PHP strings in `src/View.php`, because plain template files with undefined variables would fail PHPStan level 5. The spec allowed a different structure inside `src/`.
2. A reset or password change also logs out the user's other open sessions, using a hash fingerprint stored in the session. This is stricter than the spec and needs no schema change.
3. Statuses: a locked login gives 429 and validation errors give 422. Wrong login gives 200 with the generic message, the same for all three error cases.
4. If an admin resets their own password, they are logged out on the next request (fingerprint) and must log in with the one-time password.
