## System understanding: hvad v0 tog fejl af
v0 holdt, bortset fra to ting:
1. **Diarization (H011).** H011 blev merget, mens jeg arbejdede. `Diarizer::busy()` regnede ethvert opkald i "ventende" med hentet lyd som optaget kø. Sprungne opkald står i "ventende" for altid, så diarization ville aldrig få ledig tid. `busy()` bruger nu de samme regler som køen.
2. **Testdata med faste datoer.** Mange eksisterende tests bruger faste datoer fra oktober 2026, der allerede er ældre end 30 dage, og to tests krævede, at testens `[whisper]` er tom. Testløberens config slår derfor reglerne fra (`min_seconds = 0`, `max_age_days = 0`), og H012-testene giver selv reglerne.

## Hvad er lavet
- **`QueueRules`** (ny klasse) læser `[whisper] min_seconds` (0–120, standard 15), `max_age_days` (0–3650, standard 30) og `source_priority` (equal|zendesk|adversus, standard equal). En ugyldig værdi giver standarden og én advarsel, som ved de øvrige `[whisper]`-nøgler.
  - Den leverer betingelsen for, hvad køen må tage, køens rækkefølge, årsagen til et spring (`kort`/`gammel`) og loglinjen.
  - Reglerne regnes ud, når køen bruges, og gemmes ikke som status.
  - Manuelt valgt betyder `manual_at IS NOT NULL` eller et Adversus-opkald uden succes (F004).
- **Claim** (`Transcriber`):
  - Rækkefølgen er: fejlet sidst, så kilden efter `source_priority`, så manuelle valg efter de automatiske, og nyeste først.
  - Reglerne står også i den atomiske UPDATE.
  - Uden regler (standard i konstruktøren) gælder kun rækkefølgen. `transcribe.php` giver altid reglerne fra config.
- **Lydhentning:** Zendesk og Adversus henter nyeste først. Adversus henter stadig succes-opkald først. `source_priority` gælder kun claim, som du besluttede.
- **Migration 0008** `calls.manual_at DATETIME NULL` er expand, reversibel og idempotent, med down-fil.
- **Knappen "Transcribér dette opkald":**
  - Ruten findes nu i hele det nye UI (`Ui::modern()`).
  - Adversus kræver stadig F004, og uden F004 giver det 404 som før.
  - Zendesk får kun knappen, når opkaldet er sprunget over. Andre Zendesk-opkald giver 404 som før.
  - Et sprunget opkald får `manual_at` sat i én atomisk UPDATE, og status ændres ikke. Kvitteringen er "Opkaldet er sat i kø. Transcriptet laves, når opkaldene foran det er færdige."
  - Loftet på 50 tæller både `manual_at` og Adversus uden succes. Et valg af et "ikke valgt" Adversus-opkald sætter også `manual_at`.
- **UI:**
  - Badges: neutralt `s-ikke-valgt` med "For kort" eller "Ikke automatisk", kun når lyden er hentet.
  - Detaljen viser årsagen ("kortere end 15 sekunder" / "ældre end 30 dage") og knappen.
  - Tælleren "venter på transcription" tæller kun opkald i "transcriberer" plus dem i "ventende", som reglerne tager. Den gamle UI (`CallView`) får den samme tæller.
- **Log:** `transcribe: N opkald sprunget over (for korte X, ældre end 30 dage Y)` skrives én gang i timen, i minut 0, af slot 1. Linjen "motoren er ikke klar" tæller med de samme regler.
- **Diarization:** `Diarizer::busy()` bruger de samme regler som køen.
- **Impact** er rettet til tier 1 med begge critics. Fragmentet er `changes/H012.md`, og typen er `fejl`. Ret den, hvis du vil have en anden.

## Smoke-test (AK6, ejeren på DEV efter deploy)
Kør kommandoerne som DEV-sitets bruger i hjemmemappen.

1. **Måling før deploy (read-only):**
   ```
   cd ~ && php -r 'require getenv("HOME")."/src/Bootstrap.php"; foreach (Whisper\DB::all("SELECT source, is_success, (duration_sec > 0 AND duration_sec < 15) AS kort, (started_at < UTC_TIMESTAMP() - INTERVAL 30 DAY) AS gammel, COUNT(*) AS antal FROM calls WHERE audio_status = '\''hentet'\'' AND transcript_status = '\''ventende'\'' GROUP BY 1, 2, 3, 4") as $r) echo implode(" ", $r), "\n";'
   ```
   Hver linje viser kilde, succes, kort, gammel og antal. Gem outputtet.
2. **Config:** `vi ~/config/config.ini`. Under `[whisper]` står `source_priority = zendesk` allerede. Tilføj ingenting, så gælder standarderne (15 s og 30 dage). Gem med `:wq`.
3. **Efter deploy:**
   - Åbn opkaldslisten på DEV. "N venter på transcription" skal være faldet markant fra ca. 1009. Det nye tal skal svare til summen af de linjer i måling 1, hvor `kort` = 0 og `gammel` = 0, plus de opkald, der er i gang.
4. **Badges:**
   - Opkald under 15 s viser "For kort".
   - Opkald ældre end 30 dage viser "Ikke automatisk".
   - Begge kan stadig afspilles.
5. **Knappen:**
   - Åbn et "For kort"-opkald og tryk "Transcribér dette opkald". Kvitteringen er "Opkaldet er sat i kø …", og badget bliver "Venter".
   - Gør det samme med et "Ikke automatisk"-opkald fra Zendesk.
6. **Log efter næste hele time:**
   ```
   grep 'sprunget over' ~/logs/transcribe.log | tail -3
   ```
   Forventet: `transcribe[1]: N opkald sprunget over (for korte X, ældre end 30 dage Y)`.
7. **Rækkefølge:**
   ```
   grep 'færdig (lyd' ~/logs/transcribe.log | tail -5
   ```
   Opkald-id'erne skal være de nyeste. Med `source_priority = zendesk` kommer Zendesk-opkald først.
8. **Rollback, hvis noget er galt:** `vi ~/config/config.ini`, sæt under `[whisper]`:
   ```
   min_seconds = 0
   max_age_days = 0
   source_priority = equal
   ```
   Gem med `:wq`. Det virker fra næste minut uden deploy.

LEARNINGS: Når et nyt filter sætter tilstande, der aldrig forsvinder (her "ventende", som reglerne springer over), så tjek alle andre steder, der læser samme tilstand som "køen er ikke tom". H011's `Diarizer::busy()` ville ellers aldrig have fået ledig tid. Testdata med faste datoer bryder tidsafhængige regler med det samme. Slå reglen fra i testløberens config, og lad de nye tests give reglerne selv.
