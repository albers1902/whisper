## What was fixed, finding by finding

**1. QA F-1 (blocking), `opret-admin.php`.** Fixed.
- The password reading now lives in the new `src/SecretInput.php`.
- From a pipe, it reads one line and never calls stty.
- In a terminal, echo is turned off with stty. If that does not work (the function is disabled or stty is missing), input is refused before any prompt, with: "Kan ikke slå ekko fra i terminalen. Pipe adgangskoden ind via stdin i stedet, fx: …".
- Echo is turned back on in a `finally` block and also by `register_shutdown_function`.
- One deviation from your wording: I check `function_exists('exec')` and the exit code from `exec`, not `shell_exec`. `shell_exec` returns `null` even when it succeeds (stty prints nothing), so it cannot tell success from failure. `systemStty` only accepts `-echo` and `echo`.
- Test `test_F001-AK10_opret_admin` covers:
  - terminal without stty is refused and nothing is read;
  - terminal with stty turns echo off and on again;
  - pipe input never calls stty;
  - an unknown stty argument is refused;
  - the shutdown hook exists.

**2. QA F-2, test of NativeSessionDriver.** Added as the new test `test_F001-AK2_native_session` (CLI, temporary home folder, output buffered). It checks:
- the cookie is Secure, HttpOnly, SameSite=Lax, lifetime 0, path `/`, name `whisper_session`;
- `var/sessions` is created with 0700 and `save_path` points to it;
- strict mode and cookie-only sessions are on;
- `gc_maxlifetime` is 8 hours and GC probability is 1/100;
- `regenerate` gives a new id and deletes the old file;
- data is saved and read back;
- `destroy` deletes the file.

It also passes locally on Windows, where the 0700 check is skipped.

**3. Security S1 + QA F-8, throttling race.** Fixed.
- `LoginThrottle::begin()` records the attempt as a failure *before* bcrypt and counts only attempts with a lower id. Attempts still in progress therefore count, so a burst of parallel requests gets at most 5 through.
- If the email or IP is locked, the new row is deleted again, so the lock still ends on time.
- `succeed()` updates the row to a success.
- `/konto` now uses the same throttle for "nuværende adgangskode", keyed on the user's email and IP. It shares the counter with login.
- Tests:
  - `F001-AK3`: five unresolved parallel attempts lock the sixth; resolved successes do not lock.
  - `F001-AK9`: after 5 wrong guesses on `/konto`, the correct password gets 429 and nothing changes; login for the same email is also locked.

**4. Security S2, IPv6 /64.** Fixed. `LoginThrottle::normalizeIp`:
- IPv6 becomes `<prefix>::/64`;
- IPv4-mapped IPv6 becomes plain IPv4;
- IPv4 is unchanged.

The normalized value is used both when writing and when counting. Tests in `F001-AK3`: normalization, a new address in the same /64 is locked, a different /64 is not.

**5. Security S3 + QA F-7/F-9.** Fixed.
- **Index:** `INDEX login_attempts_created (created_at)`, added inside 0002 itself (no new migration).
- **Purge:** `maybePurge` runs about once per 50 login attempts. `purge` is still callable directly.
- **No session writes for anonymous visitors:** `last_seen` is only set for logged-in users. On top of that, `index.php` only starts a PHP session when a session cookie exists or the path is `/login`. Otherwise the request runs with an in-memory session, so bots create no session files.
- **Date format:** `last_login_at` is shown as `dd.mm.åååå hh:mm` in the list and on the edit page.
- **Tests:**
  - `F001-AK3`: the index exists and purge respects the 30-day limit.
  - `F001-AK1`: an anonymous GET writes nothing to the session.
  - `F001-AK6`: the date format.

**6. Security S4 + QA F-6, 72 bytes.** Fixed. `Password::problem` refuses more than 72 bytes with "Adgangskoden må højst være 72 byte (72 tegn, men æ, ø og å tæller som 2)." Tests in `F001-AK9`:

- 73 bytes is refused;
- 37 × æ is refused;
- `/konto` refuses 80 characters and the password stays unchanged.

**7. QA F-3, HEAD.** Fixed. HEAD is treated as GET, and a 405 response's `Allow` header includes HEAD where GET is allowed. Tests in `F001-AK1`: anonymous `HEAD /` gives 303 to `/login`, `HEAD /login` gives 200.

**8. QA F-4, confirmation pages.** Fixed.

- The edit page now has links instead of direct buttons. "Genaktiver" is still a direct button.
- Tests:

  - `F001-AK4`: the confirmation pages give 403 for a regular user.

**9. QA F-5, own account.** Fixed.

## LEARNINGS
2026-11-11 | F001 | `shell_exec('stty -echo')` cannot tell success from failure: it returns `null` both on success (no output) and when it fails. Use `exec()` with the exit code, and check `function_exists('exec')` first, since `disable_functions` may be set.
2026-11-11 | F001 | Login throttling that checks before bcrypt and records afterwards lets parallel requests through. Record the attempt first, count only lower ids, and delete the row if locked. That closes the race without GET_LOCK.
