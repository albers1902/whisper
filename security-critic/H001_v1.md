# Security Critic-review H001 (v1)

Omfang: koden i `homedir/` (health, Config, DB, migrate.php, migration 0001 og testløberen), `coworker.ini`, `.gitignore`, `launched/compliance/ACCESS.md` og `launched/DRIFT.md`. `ci.sh`, `deploy.sh` og `monitor.sh` i `homedir/cron/` er byte-identiske med `shared/install/*`. Frameworkets egne filer (`shared/`, `agents/`) har jeg ikke gennemgået linje for linje. Det er `framework.lock` og CI's opgave.

## Tjekket uden fund
- **SQL-injection:** `DB.php` bruger kun prepared statements med `ATTR_EMULATE_PREPARES=false`. Den eneste SQL-tekst med variabelt indhold er migrationsfilerne i `migrate.php`. De kommer fra repoet (betroet) og køres kun via CLI, `PHP_SAPI`-tjekket.
- **Health-svaret:** det indeholder kun `ok`/`fail`, datoer, et heltal og en SHA. Fejltekster går til `error_log`, aldrig til svaret. `last_incident` returnerer kun tidsstemplet efter regex-validering. `deployed_sha.php` læses som tekst og matches med regex, aldrig med `include`.
- **Skriveprøven:** den kører i en transaktion med `rollBack()` i `finally`, så den efterlader ingen data (AK1).
- **Secrets:** ingen hemmeligheder i git. `.gitignore` dækker `**/config/*.ini` og `config/github.token`. `features.ini` er bevidst undtaget og indeholder ingen hemmeligheder. `config.ini` ligger i hjemmemappen, uden for webroden `public_html`, og `src/` og `config/` er ikke webtilgængelige.
- **Testløberen:** den læser databasen fra `CW_DB_*`, filtrerer anførselstegn og linjeskift ud af værdierne og kræver, at de er sat.
- **Migrationer:** SHA-256-immutabilitetstjek, stop ved første fejl, og exit ≠ 0 uden config (AK2). Migration 0001 har headers og down-fil.
- **CI som grænse:** der er ingen `.github/workflows/` og ingen svækkede checks. `ci.yml` og `monitor.yml` i `shared/install` er 3-linjers stubs.
- **Feature flag:** der er ingen synlig adfærd og ingen ny brugerrettet kodesti.
- **Persondata og eksterne kald:** ingen. Det passer med impact-analysen.
- **Engineerens påstande:** jeg har ikke fundet påstande i `changes/H001.md` eller impact-filen, som diffen ikke understøtter.

## Accepterede fund

# Severity
LOW
# Risk
`/health` er offentlig og uautentificeret, og hvert kald åbner en DB-forbindelse og laver en INSERT med rollback. Det er en lille DoS-forstærkning: mange kald kan belaste DB-forbindelser. Der er ingen rate limit.
# Exploit scenario
En angriber hamrer `https://whisper.xanouso.com/health` og opbruger forbindelser eller IO på databasen. Så bliver status `degraded`, og monitor.sh kan give falsk alarm eller blokere deploy.
# Exact issue
`homedir/public_html/health.php` har hverken throttling eller cache. Designet er frameworkets kontrakt (LIFECYCLE §8), og skeletttet har ingen persondata, så effekten er begrænset til driftsforstyrrelse.
# Recommended fix
Sæt rate limit på webserver- eller proxyniveau (fx `limit_req` eller mod_evasive) for `/health`, eller cache svaret 5-10 sekunder. Gør det i et senere F- eller H-nummer, senest før der kommer rigtige data på STABLE.

# Severity
LOW
# Risk
`launched/compliance/ACCESS.md` har feltet "Gennemgået 2026-11-11" på rækker, hvor konto, oprettelses- og rotationsdato står som "udfyldes ved serveropsætning". `report.sh check` vil derfor ikke melde tokens og database-brugere som ugennemgåede, selv om de endnu ikke findes eller er rotationsdateret.
# Exploit scenario
Tokens og database-brugere oprettes ved serveropsætningen, men ACCESS.md bliver ikke opdateret. Så mangler adgangsregisteret reelle rotationsdatoer, og rotation overvåges ikke.
# Exact issue
Pladsholderne er markeret som "Gennemgået" uden at være gennemgået. Det er en proceskontrol, ikke en kode-sårbarhed.
# Recommended fix
Udfyld konti og datoer ved serveropsætningen (OPSAETNING §4) i en opfølgende docs-PR. Sæt også datoen i "Gennemgået" til serveropsætningsdagen.
