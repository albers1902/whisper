# Feature ID
H010

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Mål på DEV, om faster-whispers `BatchedInferencePipeline` gør transcription på CPU hurtigere. Tilstanden kan slås til
og fra i config, så ejeren kan sammenligne RTF og beholde den hurtigste.

# Baggrund (DEV 2026-11-12)
- Opsætningen er 2 workers × 3 tråde, turbo int8, beam 1 og VAD on (H005, H006, H007). RTF ligger typisk på 0,6–1,5
  pr. opkald, med spidser op til 2,7.
- Hvert opkald har ca. 30 s fast tid, så et klip på 8 s får RTF 4,1.
- faster-whisper har `BatchedInferencePipeline(model).transcribe(audio, batch_size=N, …)`. Den deler lyden i
  VAD-segmenter og kører dem gennem modellen i batches. På GPU er det klart hurtigere. På CPU er gevinsten usikker,
  og derfor skal den måles.
- Ejeren har bedt om målingen ("Ja, start H010", 2026-11-12).

# Requirements
- **Config:** `[whisper] engine_mode = sequential | batched` med standard `sequential`, som er uændret adfærd.
  `[whisper] batched_size` tager 1–32 med standard 8. Ugyldige værdier giver standarden og én advarsel, efter samme
  mønster som H005–H008.
- **`transcribe.py`** får `--mode sequential|batched` og `--batched-size N`. De valideres som de andre flag og afvises
  med exit 2 ved ugyldig værdi.
  - I batched-tilstand bruges `BatchedInferencePipeline` med de eksisterende indstillinger: sprog `da`, beam, VAD og
    tråde.
  - Engineeren verificerer i faster-whisper 1.2.1's kilde, hvilke parametre pipelinen tager. VAD er fx altid slået til
    i batched-tilstand. Kilden angives i v0.
  - Uddata (JSON Lines, segmenter med tid, `elapsed`) skal være uændret, så PHP-siden ikke kan se forskel.
- **Fil-batch fra H006 bevares.** Modellen indlæses én gang pr. motorstart, og pipelinen genbruges til alle filer i
  batchen.
- **Loglinjen** pr. opkald får `mode batched/sequential` med, fx
  `opkald N: færdig (lyd …, tid …, RTF …, threads 3, beam 1, vad on, mode batched)`, så RTF kan sammenlignes direkte.
- **RAM:** batched-tilstand kan bruge mere hukommelse. Engineeren estimerer forbruget i v0 for 2 workers på DEV
  (11 GiB, ca. 4,7 GB ledig). Smoke-testen indeholder `free -m`.
- `nice`, `ionice`, `HF_HUB_OFFLINE`, slots og H008-claim er uændrede.

# Acceptkriterier
- AK1: Uden nye nøgler i config kaldes motoren som i dag, uden `--mode` eller med `--mode sequential`, og uddata er
  uændret.
- AK2: `engine_mode = batched` giver `--mode batched --batched-size 8` i argv. Testen bruger falsk python.
- AK3: Ugyldige `engine_mode` og `batched_size` giver standarden og én advarsel.
- AK4: `transcribe.py` afviser ugyldige `--mode` og `--batched-size` med exit ≠ 0. Testen læser kilden og kører
  python, hvis den findes.
- AK5: Loglinjen indeholder `mode …`.

# Måling (ejerens smoke på DEV)
Ejeren sætter `engine_mode = batched` med `vi ~/config/config.ini` og lader det køre i ca. 1 time. Derefter sammenlignes
RTF i `~/logs/transcribe.log` for `mode batched` og `mode sequential`. Team Lead anbefaler den hurtigste. Hvis batched
vinder, kan standarden ændres i et senere H-nummer.

# Out of scope
GPU, andre modeller og at springe korte opkald over.

# Feature flag
Ingen. Det styres med config-nøglen. Standarden er uændret adfærd.

# Rollback
`engine_mode = sequential` eller fjern linjen. Alternativt Revert-H.
