READY_FOR_IMPLEMENTATION

# Goal
Kun indloggede brugere kan bruge Whisper, og en administrator kan oprette, ændre og deaktivere andre brugere i et
enkelt web-interface.

# Scope
- Login og logout med e-mail og adgangskode. Sessionen er sikret, og al anden adgang kræver login.
- To roller: `admin` og `user`.
- Administrationssiden `/brugere` (kun admin) kan liste brugere, oprette en bruger, ændre navn og rolle, nulstille
  adgangskode og deaktivere eller genaktivere en bruger.
- Siden `/konto` lader alle indloggede brugere skifte deres egen adgangskode.
- CLI `homedir/cron/opret-admin.php` opretter den første administrator. Den køres af ejeren som `whisperdev` og læser
  adgangskoden fra stdin.
- En enkel fælles side-ramme (header med appnavn, menu og log ud), som F002–F004 bygger videre på. Forsiden `/`
  viser indtil videre teksten "Opkald kommer her (F002)".

# Requirements
- Adgangskoder hashes med `password_hash(PASSWORD_DEFAULT)` og tjekkes med `password_verify`. Ved login rehashes
  de, hvis `password_needs_rehash` siger det. Kravet er mindst 12 tegn og intet andet.
- Sessionen: cookie med `Secure`, `HttpOnly` og `SameSite=Lax`. Session-id fornyes ved login, og sessionen ødelægges
  helt ved logout. Inaktivitets-timeout er 8 timer. Sessionsfiler gemmes i `/home/<bruger>/sessions` (findes og er
  i `open_basedir`).
- CSRF-token på alle POST-formularer. En POST uden gyldigt token giver 403 og ændrer intet.
- Login-begrænsning: efter 5 fejlede forsøg for samme e-mail eller samme IP inden for 15 min afvises yderligere
  forsøg i 15 min med samme generiske besked. Beskeden afslører aldrig, om e-mailen findes.
- En deaktiveret bruger kan ikke logge ind, og en åben session afvises ved næste request.
- Rolle og aktiv-status læses fra databasen ved hver request, ikke kun fra sessionen. En nedgradering virker derfor
  med det samme.
- Den sidste aktive administrator kan hverken deaktiveres eller nedgraderes. En admin kan heller ikke deaktivere sig
  selv.
- Når en admin opretter en bruger eller nulstiller en adgangskode, laves der en tilfældig adgangskode på 16 tegn
  (`random_bytes`). Den vises én gang på skærmen og gemmes aldrig i klartekst. Ved næste login skal brugeren skifte
  den (`must_change_password`).
- Al output escapes med `htmlspecialchars`. Al SQL går gennem prepared statements (`DB.php`).
- Sprog: dansk. Simpel, ren HTML og CSS uden JS-framework og uden eksterne CDN'er.
- `/health` er fortsat åben uden login.

# Acceptkriterier
- AK1: En anonym request til `/`, `/brugere` eller `/konto` omdirigeres til `/login`. `/health` svarer stadig uden
  login.
- AK2: Login med korrekt e-mail og adgangskode for en aktiv bruger lykkes og fornyer session-id. Forkert adgangskode,
  ukendt e-mail eller deaktiveret bruger giver samme generiske fejl.
- AK3: Efter 5 fejlede forsøg inden for 15 min (samme e-mail eller samme IP) afvises også det korrekte login, indtil
  der er gået 15 min.
- AK4: En bruger med rollen `user` får 403 på `/brugere` og på alle dens POST-handlinger.
- AK5: En admin kan oprette en bruger, og den viste engangsadgangskode virker én gang. Brugeren tvinges til at skifte
  adgangskode før alt andet. E-mailen er unik uden forskel på store og små bogstaver.
- AK6: En admin kan ændre rolle, nulstille adgangskode og deaktivere eller genaktivere en bruger. En deaktiveret
  brugers åbne session afvises ved næste request.
- AK7: Den sidste aktive admin kan ikke deaktiveres eller nedgraderes, og en admin kan ikke deaktivere sig selv.
- AK8: En POST uden gyldigt CSRF-token giver 403 og ændrer intet.
- AK9: Adgangskoder findes kun som hash i databasen, og en ny adgangskode under 12 tegn afvises.
- AK10: `opret-admin.php` opretter en aktiv admin med adgangskode fra stdin. Den afviser, hvis e-mailen findes, og
  afslutter med kode ≠ 0 ved fejl. Den kan kun køres fra CLI.
- AK11: Med flaget `[F001_brugere]` slukket for miljøet svarer `/`, `/login`, `/brugere` og `/konto` 404.
  `/health` virker uændret.

# User flow
1. Ejeren kører `php ~/repo/homedir/cron/opret-admin.php --home=. --email=<e-mail> --name=<navn>` som `whisperdev` i
   `~` og indtaster adgangskoden.
2. Admin åbner `https://dev.whisper.xanouso.com/`, ryger til `/login`, logger ind og lander på `/`.
3. Admin går til Brugere og vælger Opret bruger (e-mail, navn, rolle). Engangsadgangskoden vises én gang og kan kopieres.
4. Den nye bruger logger ind med engangsadgangskoden, ryger til `/konto` for at skifte adgangskode, og lander derefter
   på `/`.
5. Fejlvejen: ved forkert login vises "Forkert e-mail eller adgangskode". Når låsen er aktiv, vises "For mange forsøg —
   prøv igen om lidt".

# Edge cases
- To admins deaktiverer hinanden samtidig, så der ikke er flere aktive admins. Tjekket for sidste admin sker i en
  transaktion (`SELECT … FOR UPDATE`).
- En e-mail med store bogstaver eller mellemrum gemmes trimmet og med små bogstaver.
- En bruger, der er logget ind, åbner `/login`. Vedkommende omdirigeres til `/`.
- En udløbet session ved POST giver redirect til `/login`, og intet ændres.

# Constraints
- PHP 8.4 og MariaDB (DEV 12.3, STABLE 10.11). Nye tabeller oprettes med `COLLATE utf8mb4_unicode_ci`
  (SERVERKONTRAKT §3). Identifikatorer skal være lovlige i begge versioner.
- Ingen nye Composer-afhængigheder.
- PHPStan level 5 rent.

# Out of scope
- Glemt-adgangskode pr. mail. En admin nulstiller i stedet.
- 2FA, SSO og API-tokens. API-tokens kommer med MCP i F003.
- Selvregistrering.
- Selve opkaldslisten (F002).

# Data model
Migration `0002_v0.2.0_brugere.sql` (reversibel ja, destruktiv nej, idempotent ja, med down-fil):
- `users`:
  - `id` INT UNSIGNED AUTO_INCREMENT PK
  - `email` VARCHAR(190) UNIQUE NOT NULL
  - `name` VARCHAR(120) NOT NULL
  - `role` ENUM('admin','user') NOT NULL DEFAULT 'user'
  - `password_hash` VARCHAR(255) NOT NULL
  - `must_change_password` TINYINT(1) NOT NULL DEFAULT 0
  - `active` TINYINT(1) NOT NULL DEFAULT 1
  - `created_at` og `updated_at` DATETIME NOT NULL
  - `last_login_at` DATETIME NULL
- `login_attempts`:
  - `id` BIGINT UNSIGNED AUTO_INCREMENT PK
  - `email` VARCHAR(190) NOT NULL
  - `ip` VARCHAR(45) NOT NULL
  - `success` TINYINT(1) NOT NULL
  - `created_at` DATETIME NOT NULL
  - INDEX (`email`, `created_at`) og INDEX (`ip`, `created_at`)
  - Rækker ældre end 30 dage slettes ved login.

Begge tabeller har `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`.

# Decisions
