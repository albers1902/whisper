# Feature ID
F002

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Opkald fra Zendesk Talk (`trygenergidanmarkhelp.zendesk.com`) hentes automatisk, transcriberes lokalt på serveren og
vises for indloggede brugere i en liste med afspilning, transcript og download, både af ét og af alle.

# Scope
- Henter Talk-opkald med optagelse via Zendesk API (cron, inkrementelt) og gemmer metadata og lydfil på serveren.
- Lokal transcription med faster-whisper (DECISIONS #2–#3): én kø, ét job ad gangen, `nice`/`ionice`, fra cron.
- Opsætning af transcriptionsmotoren i projektets hjemmemappe via et script i `cron/`, uden root.
- Web-UI bag login (F001):
  - Opkaldslisten `/` med filtre.
  - Detaljesiden `/opkald/{id}` med lydafspiller og transcript.
  - Download af ét transcript (`.txt`) og af alle transcripts i det aktuelle filter (`.zip`).
- Status på siden: hvornår der sidst er hentet fra Zendesk, og hvor mange opkald der venter på transcription.

# Requirements
## Zendesk
- **Auth er OAuth, ikke API-token.** Zendesk har fjernet API-tokens: nye kan ikke oprettes efter 2026-10-27, og alle
  holder op med at virke 2027-04-30. Det gælder også Voice-API'et
  (support.zendesk.com/hc/en-us/articles/10851263566234). Integrationen bruger en OAuth-klient (confidential) fra
  Admin Center og henter access tokens med `client_credentials`-grant. Kun read-scopes (tickets og voice), og v0
  finder de præcise scope-navne og token-endpointet i developer.zendesk.com (OAuth-migration og
  `grant_type_tokens`).
  - Access tokenet caches i `~/var/zendesk-token.json` (0600) med udløbstid og fornyes automatisk ved udløb eller
    ved `401`.
  - Adgangen står i serverens `~/config/config.ini` og aldrig i git:
    ```
    [zendesk]
    subdomain = trygenergidanmarkhelp
    client_id = <OAuth-klientens identifier>
    client_secret = <OAuth-klientens secret>
    since = 2026-10-01
    ```
  - Mangler sektionen, gør hentningen intet og logger én linje. Siden viser så "Zendesk er ikke sat op".
- Engineeren finder i v0 det korrekte endpoint ud fra Zendesk's officielle dokumentation og angiver kilden. Kandidater:
  - Talk Incremental Export for calls.
  - Ticket-kommentarer af typen `VoiceComment` med `data.recording_url`.
  Kravet: alle opkald med optagelse fra `since` og frem. For hvert opkald gemmes Zendesk call-id og ticket-id,
  retning (ind/ud), kundens telefonnummer, agentens navn, start-tid, varighed og optagelsens URL.
- Hentningen er inkrementel med en gemt cursor og idempotent: samme opkald gemmes aldrig to gange (unik nøgle på
  Zendesk call-id eller optagelses-id). Den respekterer Zendesks rate limit (`429` + `Retry-After`) og stopper
  pænt.
- Lydfilen hentes til `~/var/recordings/<år>/<måned>/<id>.<ext>` (0600). En fejlet download prøves igen ved næste
  kørsel, højst 5 gange. Status ses på opkaldet.
- Cron: `cron/zendesk-sync.php` hvert 10. minut med `flock`, så to kørsler ikke overlapper. Scriptet starter med
  `[ -e logs/deploying ] && exit 0` som framework-kravet (LIFECYCLE §8) eller tilsvarende i PHP.

## Transcription
- `cron/whisper-setup.sh` opretter et Python-venv i `~/var/whisper/venv` og installerer `faster-whisper`. Den
  henter modellen til `~/var/whisper/models`. Scriptet kan køres igen uden skade og bruger ingen root.
  faster-whisper afkoder lyd via PyAV, så en separat ffmpeg-binær installeres kun, hvis v0 viser, at den er nødvendig.
- `cron/transcribe.php` kører hvert minut med `flock`. Den tager ét ventende opkald ad gangen (ældste først), kører
  `nice -n 19 ionice -c3 ~/var/whisper/venv/bin/python cron/transcribe.py <fil>` og gemmer resultatet.
- `cron/transcribe.py`:
  - kører `WhisperModel(<model>, device="cpu", compute_type="int8")` og `transcribe(..., language="da")`;
  - skriver JSON på stdout: segmenter med start, slut og tekst, samlet tekst, varighed og model;
  - modellen kommer fra config `[whisper] model`. Standard er `turbo`, og `large-v3` er tilladt.
- Opkaldets status er `ventende` → `transcriberer` → `færdig` eller `fejlet` (med kort fejltekst, uden stier eller
  hemmeligheder). Et opkald, der hænger i `transcriberer` i over 2 timer, sættes tilbage til `ventende`. Højst 3
  forsøg.
- Transcriptet gemmes i databasen: fuld tekst og segmenter som JSON.

## UI (bag F001-login, alle roller)
- `/` erstatter pladsholderen og viser opkaldslisten, nyeste først, 50 pr. side.
  - Kolonner: dato og tid, retning, telefonnummer, agent, varighed, Zendesk-ticket (link til
    `https://trygenergidanmarkhelp.zendesk.com/agent/tickets/<id>`) og status for transcription.
  - Filtre: periode (fra/til), retning, agent og fritekstsøgning i transcripts.
- `/opkald/{id}` viser metadata, en lydafspiller (`<audio controls>`) og transcriptet med tidsstempler
  (`[mm:ss] tekst`), og har knappen "Download transcript (.txt)".
- `/opkald/{id}/lyd` streamer lydfilen gennem PHP med login-tjek og `Range`-understøttelse, så man kan spole. Den
  korrekte `Content-Type` og `Cache-Control: private, no-store` sendes med. Filen ligger aldrig i webroden.
- `/opkald/{id}/transcript.txt` er transcriptet som UTF-8-tekst med en hoved-blok (dato, retning, nummer, agent,
  ticket).
- `/opkald/download.zip?<samme filtre>` er alle færdige transcripts i filtret som `.txt`-filer i én zip, højst 2000
  ad gangen. Filnavnet er `ÅÅÅÅ-MM-DD_HHMM_<retning>_<ticket>.txt`.
- Al output escapes. CSP fra F001 bevares. `<audio>` kræver `media-src 'self'`.

# Acceptkriterier
- AK1: Sync med et mocket Zendesk-svar gemmer opkaldene med alle felter. En ny kørsel med samme data giver ingen
  dubletter, og cursoren gemmes og bruges.
- AK2: Sync håndterer `429` med `Retry-After` uden datatab, stopper ved netværksfejl uden halve rækker, og gør intet,
  når `[zendesk]` mangler.
- AK3: Optagelsen hentes til `var/recordings/...` med 0600. En fejlet download markeres og prøves igen, højst 5 gange.
- AK4: `transcribe.php` tager ét ventende opkald, kører motoren (mocket i test) og gemmer tekst og segmenter. Status
  går til `færdig`, ved fejl til `fejlet` med fejltekst, og et hængende job sættes tilbage efter 2 timer. To samtidige
  kørsler behandler aldrig samme opkald.
- AK5: Opkaldslisten viser felterne, sorteres nyeste først, pagineres og filtreres på periode, retning, agent og
  fritekst.
- AK6: Detaljesiden viser transcript med tidsstempler, og `.txt`-download indeholder hoved-blok og tekst i UTF-8.
- AK7: `/opkald/{id}/lyd` kræver login, understøtter `Range` (206 med korrekt `Content-Range`) og afviser ugyldigt
  id og sti-manipulation.
- AK8: `download.zip` indeholder netop de færdige transcripts i filtret, med de rigtige filnavne, og kræver login.
- AK9: Anonyme requests til alle F002-ruter omdirigeres til `/login`. Med flaget `[F002_zendesk]` slukket viser `/`
  F001's pladsholder, og F002-ruterne svarer 404.
- AK10: `client_secret`, access token og lydfil-stier vises aldrig i UI, fejltekster eller logs. Logs indeholder kun
  opkalds-id. Token-cachen er 0600, og et udløbet eller afvist (`401`) token fornyes én gang automatisk.

# User flow
1. Ejeren opretter en OAuth-klient (confidential) i Zendesk Admin Center og skriver `[zendesk]` i `config.ini`. Ejeren kører `~/cron/whisper-setup.sh`
   en gang, eller cron gør det, hvis motoren mangler (v0 afgør hvilken af de to).
2. Inden for 10 min dukker opkald fra `since` op i listen med status "Venter".
3. Transcription kører ét ad gangen, og status skifter til "Færdig".
4. Brugeren klikker et opkald, lytter, læser transcriptet og henter `.txt`.
5. Brugeren filtrerer på periode og henter "Download alle (.zip)".

# Edge cases
- Et opkald uden optagelse (fx ubesvaret) gemmes ikke, eller gemmes som "ingen optagelse" og transcriberes aldrig.
  v0 vælger og begrunder.
- Meget lange opkald (over 60 min) transcriberes som alle andre. `max_execution_time` i CLI er ingen grænse.
- Lydfilen er slettet eller mangler på disk. Detaljesiden siger det, og afspilleren vises ikke.
- Zendesk ændrer et opkald senere (fx varighed). Det opdateres ved næste sync, hvis API'et leverer det.
- Disken er fuld. Download fejler med status, og intet halvt gemmes.

# Constraints
- PHP 8.4 CLI og web og MariaDB. Nye tabeller oprettes med `COLLATE utf8mb4_unicode_ci`.
- Ingen nye Composer-afhængigheder. HTTP-kald laves med `curl`-udvidelsen. Til zip bruges `ZipArchive`; mangler
  den, siger v0 det, og der vælges et alternativ (fx `.tar` med PharData) uden root.
- Python-pakker kommer kun ind via `whisper-setup.sh` i venv'et. Python-scriptet testes ikke i CI. CI mocker
  motoren, fordi CI-brugeren ikke må hente modeller.
- Lyd og transcripts er persondata (kunders stemme, telefonnummer og samtaleindhold). De forlader aldrig serveren
  (DECISIONS #2).

# Out of scope
- Adversus (F004) og MCP (F003).
- Manuel upload af lydfiler.
- Sletning og retention af lyd og transcripts. Det kommer i et senere ID og står som risiko.
- Talergenkendelse (hvem siger hvad).

# Data model
Migration `0003_v0.3.0_opkald.sql` (reversibel ja, destruktiv nej, idempotent ja, med down-fil). Forslag, som
engineeren må tilpasse i v0:
- `calls`:
  - `id` PK
  - `source` ENUM('zendesk')
  - `external_id` VARCHAR(64), UNIQUE (`source`, `external_id`)
  - `ticket_id` BIGINT NULL
  - `direction` ENUM('inbound','outbound')
  - `customer_phone` VARCHAR(40)
  - `agent_name` VARCHAR(120)
  - `started_at` DATETIME
  - `duration_sec` INT
  - `recording_url` VARCHAR(500)
  - `audio_path` VARCHAR(255) NULL
  - `audio_status` ENUM('venter','hentet','fejlet')
  - `audio_attempts` TINYINT
  - `transcript_status` ENUM('ventende','transcriberer','færdig','fejlet','ingen')
  - `transcript_attempts` TINYINT
  - `transcript_error` VARCHAR(255) NULL
  - `claimed_at` DATETIME NULL
  - `created_at`, `updated_at`
  - Indeks på `started_at` og `transcript_status`.
- `transcripts`: `call_id` PK/FK, `text` MEDIUMTEXT, `segments_json` MEDIUMTEXT, `model` VARCHAR(40),
  `language` CHAR(2), `created_at`. FULLTEXT-indeks på `text`, hvis det virker i både MariaDB 10.11 og 12.3, ellers
  `LIKE`.
- `sync_state`: `source` PK, `cursor` VARCHAR(255), `last_run_at`, `last_ok_at`, `last_error` VARCHAR(255).

# Decisions

   150 s. (Team Lead, 2026-11-11)
3. CI mocker motoren. — CI-brugeren må ikke hente modeller, og testene skal være hurtige. (Team Lead, 2026-11-11)
