# Feature ID
F005

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Whisper får et moderne, roligt og tilgængeligt UI (WCAG 2.2 AA), som kundeservice gider bruge hver dag: hurtig
søgning, lyt og læs side om side, og ingen tabt kontekst.

# Kilder (bindende)
- UX: `ui-ux/F005_design_v1.md`, afsnit 0–9. Prioriteten er SKAL 1–10 og BØR 11–19. KAN 20–26 laves kun, hvis det er
  billigt. Undtaget er punkt 24 (forrige og næste opkald), som udskydes.
- Visuelt: `graphic-design/F005_visual_v1.md` (tokens, lyst og mørkt tema, komponenter, ikoner, CSS-struktur). Ved
  konflikt om farver og mål gælder det visuelle brief, og ved konflikt om adfærd og tekster gælder UX-briefet.
- Visuel reference: Claude Design-lærredet "Whisper UI 2026" (https://claude.ai/artifact/RPsUbpGfccGjjkYtWo9cbJ).

# Scope
- Ny `homedir/public_html/assets/app.css` efter det visuelle brief, med begge temaer.
- Ny `homedir/public_html/assets/app.js` efter UX §4 (tidsstempler, kopiér, aktuel linje og hastighed), under 150
  linjer, ingen afhængigheder og kun progressive enhancement.
- Skabeloner i `View.php`, `CallView.php` og de øvrige View-dele:
  - header med `aria-current`, skip-link og brugermenu;
  - bredder;
  - liste (filterkort, chips, statuslinje, row-link, data-label, pager, zip-tekst);
  - detalje (to kolonner, sticky afspiller, segmenter, fremhævning, tilstandstabellen, rollestyrede beskeder);
  - login, konto (`.card.medium`, sektioner; F003's MCP-sektion beholdes og får de nye klasser og kopiér-knapper);
  - brugere og fejlsider.
- Listens kontekst i URL'en til detaljen og tilbage (UX §2).
- Server-side fremhævning af søgeord med tokenisering før escaping (UX §3.4, D6) og søgeuddrag i listen (BØR 15).

# Ikke i scope
- Ændringer i data, migrationer, Zendesk-sync, transcription, MCP-protokollen og adgangsregler.
- Brand-logo fra TrygEnergi. Mærket med de fem bølgebjælker bruges, indtil ejeren siger andet.

# Acceptkriterier
- AK1: Ingen `style=""`, `<style>`, inline `<script>` eller `on*`-attributter i noget HTML-svar. CSP'en er uændret.
  `app.js` og `app.css` indlæses fra `/assets/`.
- AK2: Header: det aktive punkt har `aria-current="page"` (detaljesider markerer forælderen), og der er et skip-link
  til `#indhold` og en brugermenu til højre.
- AK3: Links fra listen til detaljen bærer listens filtre og side. Tilbage-linket på detaljen fører til `/?<samme
  query>`.
- AK4: Badges følger UX §3.2 med tekst, klasse og en "Ukendt"-fallback, og samme kortlægning bruges i liste og detalje.
- AK5: Detaljen viser segmenter i `<ol class="transcript">` med `button.ts[data-start]` (disabled uden JS) eller
  `span.ts` uden afspillelig lyd. Søgeord fremhæves med `<mark>`, det første med `id="fund-1"`, og "N fund for «q»"
  vises. Fremhævningen escaper korrekt (fx `<script>` og `&amp;` i transcriptet).
- AK6: Alle tilstande i UX §3.4's tabel giver den beskrevne tekst. Tekniske fejl står i `<details>`, og admin-only
  tekster vises kun for admin.
- AK7: Systembeskeder på listen er rollestyrede efter UX §3.3's tabel.
- AK8: Aktive filtre vises som chips, der hver linker til query'en uden netop det filter. "Viser a–b af N opkald" og
  `nav.pager` vises, og zip-knappen har den nye tekst og skjules ved 0.
- AK9: Kopiér-knapper (`data-copy`, `hidden` i HTML) findes på engangskode, MCP-nøgle, MCP-konfiguration og
  transcript. Der er en fælles `role="status"`-region i layoutet.
- AK10: Søgeuddrag i listen (ved `q`) har højst 160 tegn omkring første fund, fremhævet og escaped korrekt.
