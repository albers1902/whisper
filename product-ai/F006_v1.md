# Feature ID
F006

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Whisper kan tilføjes i Claude som en custom connector, kun med URL'en `https://<vært>/mcp`. Brugeren logger ind med
sin Whisper-bruger i et OAuth-vindue og godkender adgangen. Der er ingen nøgle at kopiere og ingen Node.js eller
`mcp-remote` (ejeren 2026-11-12, DECISIONS #47).

# Baggrund
- F003 byggede `/mcp` med personlige bearer-nøgler (`wsp_…`) til Claude Desktop via `mcp-remote`. OAuth blev holdt
  uden for scope: "OAuth 2.1 med dynamisk klientregistrering (Claude.ai-connector uden `mcp-remote`). Det kan komme i et
  senere ID."
- Ejeren vil bruge "Tilføj custom connector" i Claude (claude.ai og Claude Desktop). Der angives kun en URL, og
  verifikationen gennemføres i browseren.
- Claude's connector forventer MCP-autorisation efter MCP-specifikationen (OAuth 2.1 med PKCE, metadata for protected
  resource og authorization server, og dynamisk klientregistrering). Engineeren verificerer den aktuelle version af
  specifikationen og Claude's krav i v0 og angiver kilderne. Det gælder især redirect-URI'er for Claude's callback,
  understøttet transport (streamable HTTP) og protokolversion.

# Requirements

## OAuth-server i den eksisterende PHP-app (bag flaget `F006_oauth`)
- **Metadata:**
  - `GET /.well-known/oauth-protected-resource` (RFC 9728, også i den sti-specifikke variant, hvis specifikationen
    kræver det) peger på authorization serveren, som er samme vært.
  - `GET /.well-known/oauth-authorization-server` (RFC 8414) angiver endpoints, `code_challenge_methods_supported:
    ["S256"]`, `grant_types_supported: ["authorization_code","refresh_token"]` og `response_types_supported: ["code"]`.
- **Dynamisk klientregistrering** (`POST /oauth/register`, RFC 7591):
  - Kun public clients (`token_endpoint_auth_method: none`).
  - `redirect_uris` skal være https og på en allowlist i config, `[oauth] redirect_hosts`. Standarden er de værter,
    Claude bruger, og som engineeren verificerer, fx `claude.ai` og `claude.com`. `localhost` tillades kun på DEV
    (`[app] env = dev`).
  - Registreringen har rate limit. Klienter, der aldrig bliver brugt, ryddes efter 30 dage.
- **Autorisation** (`GET/POST /oauth/authorize`):
  - Authorization code flow med PKCE, kun S256. `state` returneres uændret, og `resource` (RFC 8707) valideres mod
    `https://<vært>/mcp`.
  - Er brugeren ikke logget ind, vises Whispers eksisterende login (med F001's throttling), og flowet fortsætter
    bagefter.
  - Derefter vises en godkendelsesside: "<klientens navn> vil have læseadgang til dine opkald og transcripts i
    Whisper". Knapperne er Godkend og Afvis. Godkendelsen er POST med CSRF.
  - Koden er engangs, gyldig i højst 60 s og bundet til klient, redirect_uri, PKCE-challenge og bruger.
- **Token** (`POST /oauth/token`):
  - Ombytter koden for et access token (opaque, ca. 1 time) og et refresh token (rotation ved hver brug, ca. 30 dage).
  - Kun hashes gemmes i DB, som for F003-nøglerne.
  - Genbrug af en kode eller et roteret refresh token tilbagekalder hele kæden.
- **`/mcp`:**
  - Accepterer både F003-nøgler (`wsp_…`) og OAuth access tokens. Samme værktøjer og samme rettigheder som brugeren.
  - Uden gyldigt token svarer den 401 med `WWW-Authenticate: Bearer resource_metadata="…"`, så Claude kan finde
    metadata.
  - Engineeren sikrer, at transporten (streamable HTTP, protokolversion) virker med Claude's connector. Den nuværende
    implementation svarer på en ældre protokolversion (DECISIONS #21/#22), så det skal tjekkes.
- **Tilbagekald:**
  - Konto-siden viser "Forbundne apps" (klientnavn, oprettet, sidst brugt) med en knap til at tilbagekalde.
  - En ny adgangskode tilbagekalder alle tokens, som F003-nøglerne gør (DECISIONS #24).
  - En administrator, der fjerner en bruger, tilbagekalder også brugerens tokens.
- **Konto-siden:** vejledningen bliver "Tilføj i Claude: Indstillinger → Connectors → Tilføj custom connector → URL
  `https://<vært>/mcp`". Den nuværende `mcp-remote`-vejledning med nøgle flyttes ned under "Avanceret: nøgle til
  Claude Desktop via mcp-remote".
- **Log:** OAuth-hændelser (registrering, godkendelse, afvisning, tokenudstedelse, tilbagekald) skrives i AccessLog
  uden tokens og koder.

# Acceptkriterier
- AK1: Metadata-endpoints svarer med korrekt JSON, og `/mcp` uden token giver 401 med `resource_metadata`.
- AK2: Dynamisk registrering accepterer en https-redirect på allowlisten og afviser andre værter, http og manglende
  felter.
- AK3: Hele flowet (register → authorize med login og godkendelse → token → `/mcp` tools/list) virker med PKCE S256.
  Forkert verifier, genbrugt kode, udløbet kode og forkert redirect_uri afvises.
- AK4: Refresh roterer, og genbrug af et gammelt refresh token tilbagekalder kæden.
- AK5: Afvis på godkendelsessiden returnerer `error=access_denied` til redirect_uri med state.
- AK6: Tilbagekald på Konto, ny adgangskode og fjernet bruger gør tokens ugyldige med det samme.
- AK7: F003-nøgler virker uændret på `/mcp`.
- AK8: Med flaget slukket findes OAuth-endpoints ikke (404), og `/mcp` opfører sig som i dag.
- AK9: Smoke på DEV: ejeren tilføjer `https://dev.whisper.xanouso.com/mcp` som custom connector i Claude, logger ind,
  godkender og kan spørge efter opkald.

# Out of scope
Confidential clients, scopes ud over læseadgang, andre identitetsudbydere og STABLE.

# Feature flag
`F006_oauth`: til på dev, fra på test og stable.

# Rollback
Slå flaget fra. Så virker F003-nøglerne stadig. Alternativt Revert-F. Migrationen er reversibel.
