# Feature ID
F003

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
En indlogget Whisper-bruger kan forbinde Claude Desktop til Whisper via MCP og bede Claude om at søge i, læse og
analysere opkaldstranscripts, uden at downloade filer.

# Scope
- En remote MCP-server i appen på `https://<vært>/mcp` med Streamable HTTP-transport (JSON-RPC 2.0 over POST, svar som
  `application/json`, uden SSE-strøm). Den er stateless, så hver request står alene. Det passer til PHP-FPM.
- Personlige MCP-nøgler (bearer tokens) pr. bruger. De oprettes og tilbagekaldes på `/konto`, vises kun én gang og
  gemmes som hash.
- Read-only værktøjer (tools) over F002's data:
  - `search_calls`: fritekst og filtre (periode, retning, agent), returnerer en liste med metadata og et kort uddrag;
  - `get_transcript`: fuld transcript-tekst med tidsstempler og metadata for ét opkald;
  - `list_recent_calls`: de seneste N opkald med metadata;
  - `call_stats`: antal opkald pr. dag, retning og agent i en periode (ingen tekst).
- En vejledning i UI'et (`/konto`) til Claude Desktop: den præcise `claude_desktop_config.json`-blok med `mcp-remote`
  og `Authorization: Bearer`-header.

# Requirements
## Protokol
- MCP-spec revision 2025-06-18 (eller nyeste stabile, som engineeren finder på modelcontextprotocol.io; kilden
  citeres i v0).
- Metoderne `initialize`, `notifications/initialized`, `ping`, `tools/list` og `tools/call` understøttes.
  Andre metoder giver JSON-RPC-fejlen `-32601`.
- `initialize` svarer med `protocolVersion`, `capabilities: {tools: {}}` og `serverInfo {name: "whisper", version}`.
- Værktøjernes `inputSchema` er JSON Schema. Svar på `tools/call` er `content: [{type: "text", text: …}]` og, hvor det
  giver mening, `structuredContent`.
- `Origin`-headeren valideres (MCP-spec, DNS-rebinding): requests med en Origin, der ikke er sitets egen, afvises.
  Requests uden Origin (CLI-klienter som mcp-remote) tillades.
- GET på `/mcp` giver 405 (ingen SSE-strøm), og DELETE giver 405.

## Adgang
- Hver request kræver `Authorization: Bearer <nøgle>`. Nøglen findes som SHA-256-hash i `mcp_tokens`, er ikke
  tilbagekaldt og tilhører en aktiv bruger. Brugerens rolle og aktiv-status læses fra databasen ved hver request (som
  F001).
- Uden gyldig nøgle svares HTTP 401 med `WWW-Authenticate: Bearer` og ingen data.
- Nøgler har formatet `wsp_` efterfulgt af 32 tilfældige bytes i base64url fra `random_bytes`. Kun de første 8 tegn
  (`wsp_xxxx`) gemmes i klartekst til visning.
- Hver bruger kan have højst 5 aktive nøgler, hver med et navn (fx "Claude Desktop – laptop"). Nøgler kan tilbagekaldes
  på `/konto` (POST med CSRF). `last_used_at` opdateres højst én gang i minuttet.
- Rate limit: højst 60 requests pr. minut pr. nøgle. Derover gives 429 med `Retry-After`.
- Flaget `[F003_mcp]` slukket betyder, at `/mcp` svarer 404, og at nøgle-sektionen på `/konto` ikke vises.

## Værktøjer
- Kun læsning. Ingen værktøjer ændrer data, starter jobs eller viser lydfiler eller filstier.
- Alle resultater er begrænset:
  - `search_calls` og `list_recent_calls` returnerer højst 50 rækker (standard 20);
  - `get_transcript` returnerer højst 200 000 tegn, og afkortning markeres;
  - `call_stats` dækker højst 366 dage.
- Datoer er ISO `YYYY-MM-DD` og valideres som i F002. Ukendte argumenter afvises med `isError: true` og en dansk
  fejltekst.
- `search_calls` genbruger F002's søgning (`Calls::search`), så resultaterne er de samme som i UI'et.
- Hvert opkald i resultaterne har `call_id`, dato og tid, retning, varighed, agent, ticket-id og et link til
  `/opkald/{id}` i Whisper. Telefonnumre medtages, fordi de også vises i UI'et for alle brugere (F002).
- Hvert `tools/call` logges i `logs/adgang.log` (F002's `AccessLog`) med `bruger=<id> mcp <værktøj>`,
  `opkald=<id>` ved `get_transcript`, og antal rækker. Argumentværdier og tekst logges ikke.

## UI (`/konto`)
- Sektionen "Claude Desktop (MCP)" har en liste over egne nøgler (navn, prefix, oprettet, sidst brugt) og formularerne
  "Opret nøgle" og "Tilbagekald".
- Efter oprettelse vises nøglen én gang, sammen med en færdig konfigurationsblok:
  ```json
  {
    "mcpServers": {
      "whisper": {
        "command": "npx",
        "args": ["-y", "mcp-remote@<låst version>", "https://<vært>/mcp", "--header", "Authorization:${WHISPER_AUTH}"],
        "env": { "WHISPER_AUTH": "Bearer <nøgle>" }
      }
    }
  }
  ```
  Engineeren tjekker i v0 den præcise syntaks for `mcp-remote` (npm) og låser en version. Hvis Claude Desktop's egne
  "custom connectors" understøtter en bearer-header direkte, nævnes det som et alternativ.
- En kort vejledning: hvor `claude_desktop_config.json` ligger på Windows og macOS, at Node.js kræves for `npx`, og at
  Claude Desktop skal genstartes.

# Acceptkriterier
- AK1: `initialize` med en gyldig nøgle svarer med `protocolVersion`, `capabilities.tools` og `serverInfo`.
  `tools/list` viser de fire værktøjer med `inputSchema`.
- AK2: Uden nøgle, med en forkert nøgle, med en tilbagekaldt nøgle eller med en nøgle fra en deaktiveret bruger svares
  401 uden data.
- AK3: `search_calls` med fritekst og filtre giver samme opkald som F002's liste, højst 50 rækker, og ugyldige datoer
  eller ukendte argumenter giver `isError`.
- AK4: `get_transcript` giver tekst med tidsstempler og metadata, afkortes over loftet med markering, og et ukendt id
  giver `isError` uden detaljer.
- AK5: `call_stats` tæller korrekt pr. dag, retning og agent og afviser perioder over 366 dage.
- AK6: En nøgle oprettes på `/konto` (CSRF), vises én gang, gemmes kun som hash med prefix, højst 5 aktive. Den kan
  tilbagekaldes, og en tilbagekaldt nøgle virker ikke længere.
- AK7: Over 60 requests pr. minut pr. nøgle giver 429 med `Retry-After`.
- AK8: En fremmed `Origin` afvises. GET og DELETE på `/mcp` giver 405, og en ukendt metode giver `-32601`.
- AK9: Med `[F003_mcp]` slukket svarer `/mcp` 404, og nøgle-sektionen vises ikke.
- AK10: Hvert `tools/call` logges i `adgang.log` uden argumentværdier eller tekst. Nøgler optræder aldrig i logs,
  fejltekster eller HTML efter visningen.

# Out of scope
- OAuth 2.1 med dynamisk klientregistrering (Claude.ai-connector uden `mcp-remote`). Det kan komme i et senere ID.
- Skrivende værktøjer, adgang til lydfiler, Adversus (F004) og prompts/resources i MCP.

# Data model
Migration `0004_v0.4.0_mcp_tokens.sql` (reversibel ja, destruktiv nej, idempotent ja, med down-fil):
- `mcp_tokens`:
  - `id` PK
  - `user_id` FK til `users` (cascade)
  - `name` VARCHAR(80)
  - `prefix` CHAR(8)
  - `token_hash` CHAR(64), UNIQUE
  - `created_at`, `last_used_at` NULL, `revoked_at` NULL
  - indeks på `user_id`
- Rate limit: en simpel tabel `mcp_rate` (`token_id`, `window_start`, `count`) eller en fil i `var/`. Engineeren
  vælger.
- `COLLATE utf8mb4_unicode_ci`.

# API surface
- `POST /mcp`: JSON-RPC 2.0 med bearer-auth.
- `GET` og `DELETE /mcp`: 405.
- `POST /konto/mcp-noegle` og `POST /konto/mcp-noegle/{id}/tilbagekald`: CSRF og login.

# Decisions
1. Remote MCP i den eksisterende PHP-app med bearer-nøgle og `mcp-remote` i Claude Desktop. — Ingen ny tjeneste og
   intet OAuth-maskineri i første omgang. Brugeren skal blot indsætte én blok. (Team Lead, 2026-11-11)
2. Stateless Streamable HTTP uden SSE. — PHP-FPM har 150 s timeout, og alle værktøjer svarer straks.
   (Team Lead, 2026-11-11)
3. Kun read-only værktøjer. (Team Lead, 2026-11-11)
