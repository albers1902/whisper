# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Coworker Framework 5.42 er installeret i det tomme projekt albers1902/whisper, så DEV-serveren kan køre CI, deploy og
health, før det første F-nummer bygges.

# Scope
- Frameworkets kopi fra master (CLAUDE.md "Ny framework-version" trin 4).
- `bash shared/report.sh install`: ci.sh, monitor.sh og deploy.sh uændret i `homedir/cron/`.
- `coworker.ini`: PHP 8.4, repo `albers1902/whisper`, health for dev (`dev.whisper.xanouso.com`) og stable
  (`whisper.xanouso.com`), ingen migrations-baseline. Ejeren har besluttet, at kun DEV er i brug indtil videre (2026-11-11).
- Minimalt PHP-skelet i `homedir/`: `/health` med felterne fra LIFECYCLE §8, `cron/migrate.php`, migration 0001 med
  headers og down-fil, en testløber der skriver `junit.xml` og læser databasen fra `CW_DB_*`, og `config/features.ini`.
- `launched/DRIFT.md` og `launched/compliance/ACCESS.md` med det, der er kendt.

# Scope-kategorisering
Alt: (2) Infrastruktur.

# Ikke i scope
Produktfunktioner (login, Zendesk, transcription, MCP, Adversus) kommer i F-numre.

# Acceptkriterier
- AK1: `/health` svarer JSON med `sha`, `status`, `db_read`, `db_write`, `backup_last_ok`, `restore_last_ok`,
  `restore_rto_min` og `last_incident`. Skriveprøven efterlader ingen data. Er databasen nede, er status `degraded`.
  Svaret indeholder aldrig fejltekster, stier eller hemmeligheder.
- AK2: `cron/migrate.php` kører alle migrationer, kan køres igen uden ændringer, afviser en ændret allerede kørt
  migration og afslutter med kode ≠ 0 ved fejl eller manglende config.

# Feature flag
Intet. Der er ingen synlig adfærd.
