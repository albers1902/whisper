# Feature ID
H006

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Whisper-modellen indlæses én gang pr. kørsel i stedet for én gang pr. opkald, så korte opkald transcriberes markant
hurtigere. Loggen viser indlæsningstiden for sig, så effekten kan måles.

# Baggrund (målt på DEV 2026-11-12 efter H005)
- Fire korte opkald på 29–57 s lyd tog 30–44 s hver (RTF 0,77–1,10) med threads 5, beam 1 og vad on.
- `ProcessEngine` starter `cron/transcribe.py` pr. opkald. Den laver `WhisperModel(...)` hver gang og indlæser
  dermed turbo-modellen (ca. 1,6 GB) forfra.
- Antagelse, der skal måles: en stor del af tiden er model-indlæsning, ikke transcription.

# Requirements
- `transcribe.py` får en batch-tilstand, hvor modellen indlæses én gang og flere filer transcriberes:
  - input er en liste af absolutte lydstier (argv, efter `--`), højst `--batch-max` (1–50);
  - output er JSON Lines på stdout: én linje pr. fil med `file` (samme sti som input), resultat eller `error`,
    `duration` og `elapsed`. Til sidst kommer én linje med `load_seconds` for indlæsningen;
  - en fejl på én fil (fx korrupt lyd) giver en `error`-linje for den fil og fortsætter med de næste;
  - de eksisterende flag (`--threads`, `--beam`, `--vad`, `--model`, `--models`) og valideringen er uændrede, og
    `HF_HUB_OFFLINE=1` gælder som før.
- `Transcriber`/`ProcessEngine` claimer op til N ventende opkald atomisk (N fra `[whisper] batch`, standard 10, 1–50)
  og kalder motoren én gang for hele batchen. Hvert opkald gemmes for sig, så snart resultatet er læst, og det sker
  stadig inde i 50-minutters-rammen og med `flock`.
- Tidsgrænsen gælder for hele batchen: summen af max(2 t, 4 × varighed)-reglerne, dog højst 50 min. Rammes grænsen,
  stoppes processen (SIGTERM, derefter SIGKILL). Opkald, der allerede har et resultat, gemmes. Resten sættes tilbage
  til `ventende` uden at bruge et forsøg, undtagen det opkald, der var i gang, som tæller som ét forsøg.
- Loggen:
  - pr. opkald: `opkald N: færdig (lyd m:ss, tid m:ss, RTF 0,xx, threads 5, beam 1, vad on)`, hvor `tid` er selve
    transcriptionstiden for filen, uden indlæsning;
  - pr. batch: `batch: K opkald, model indlæst på m:ss, i alt m:ss`.
- `[whisper] batch = 1` giver den gamle opførsel med ét opkald pr. kald, så der er en rollback via config.

# Acceptkriterier
- AK1: Med 3 ventende opkald og `batch = 10` kaldes motoren én gang med 3 filer (falsk python, der logger sit argv og
  svarer med JSON Lines), og alle 3 gemmes som færdige.
- AK2: En `error`-linje for én fil markerer kun det opkald som fejlet (backoff som i dag). De andre gemmes.
- AK3: Timeout midt i batchen: opkald med resultat er gemt, det igangværende tæller ét forsøg, og resten er `ventende`
  med uændrede forsøg.
- AK4: Loggen har linjen pr. opkald med transcriptionstid og batchlinjen med indlæsningstid.
- AK5: `batch = 1` giver ét opkald pr. kald. Ugyldig `batch` giver standarden og én advarsel (samme mønster som H005).
- AK6: `transcribe.py` validerer `--batch-max` og antallet af filer, og afviser relative stier og stier med `..`.
  Testen læser scriptet, og kører det, hvis python3 findes.

# Out of scope
Flere samtidige processer, GPU og andre modeller.

# Feature flag
Ingen. Det er en ydelsesrettelse bag F002's flag.

# Rollback
Revert-H, eller `[whisper] batch = 1` i config.
