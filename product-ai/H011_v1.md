# Feature ID
H011

# Version
v1

# Status
READY_FOR_IMPLEMENTATION

# Goal
Transcripts viser, hvem der taler: "Agent" og "Kunde", eller "Taler 1" og "Taler 2", når det ikke kan afgøres. Det
gælder i UI'et, .txt, zip og MCP. Talerne findes lokalt på serveren med en let diarization-model, uden GPU, og ingen lyd
forlader serveren (DECISIONS #2).

# Baggrund
- Ejeren (2026-11-12): "hvorfor skriver transcripts ikke hvem der taler?" og senere "Ja, start H011".
- Whisper laver kun tekst. Zendesk-optagelserne er mono (målt: `mono 22050`), så agent og kunde kan ikke skilles ad på
  kanal. Adversus-formatet er ikke målt endnu.
- Maskinen har 6 vCPU, 2 whisper-workers og ingen GPU. Diarization skal derfor være let. Forslaget er sherpa-onnx
  speaker diarization (ONNX: segmentering, fx pyannote-segmentation-3.0 i ONNX, plus en speaker-embedding-model) uden
  torch. Engineeren vælger og begrunder model og version i v0, verificerer licenser, og låser afhængigheder som i H003.

# Requirements
- **Hvornår diarization kører:** efter transcription for hvert opkald, i samme motorproces, så lyden kun afkodes én
  gang, hvis det kan lade sig gøre. Den kører med 2 talere som standard, eller med automatisk antal, hvis modellen
  understøtter det godt.
- **Tale på segmenter:** hvert whisper-segment får en taler (`speaker`: 0/1/…) efter størst tidsmæssigt overlap med
  diarization-intervallerne. Segmenter, der dækker et talerskifte, må deles ved skiftet, hvis det er enkelt. Ellers
  bruges størst overlap.
- **Roller:**
  - Taleren, hvis tekst indeholder agentmarkører, bliver "Agent". Markørerne er fx "du snakker med", "du taler med",
    "mit navn er … fra", "fra Tryg Energi". Listen ligger i config `[diarization] agent_phrases`, og standardlisten er
    i koden.
  - Den anden taler bliver "Kunde".
  - Kan det ikke afgøres, er talerne "Taler 1" og "Taler 2", ordnet efter, hvem der taler først.
- **Stereo:** hvis en optagelse er stereo med én taler pr. kanal, bruges kanalerne i stedet for modellen, fordi det er
  sikrere og billigere. Engineeren afgør i v0, om det skal med nu, eller når Adversus-formatet kendes.
- **Lagring:** taleren gemmes pr. segment sammen med transcriptet. Eksisterende transcripts uden taler vises som i dag.
  Ingen re-transcription af gamle opkald, men en admin-mulighed for at køre diarization på færdige opkald er OK, hvis
  den er billig.
- **Visning:**
  - **UI:** talerens rolle står foran teksten. Er det samme taler i flere segmenter i træk, vises rollen kun ved
    skift.
  - **.txt og zip:** `[00:12] Agent: …`.
  - **MCP:** `Agent:` / `Kunde:` i teksten. Det strukturerede felt `speaker` er valgfrit.
- **Config:** `[diarization] enabled = on|off`. Standard er `on` på dev og `off` ellers, eller via feature flag efter
  frameworkets mønster. Ugyldige værdier giver standarden og én advarsel. Med `off` er alt som i dag.
- **Log:** loglinjen pr. opkald får diarizationens tid med, fx `… diar 0:04 (2 talere, agent fundet)`, så CPU-prisen
  kan måles.
- **Fejl:** fejler diarization for et opkald, gemmes transcriptet uden taler. Det kaster ikke opkaldet i fejl. Det
  logges som én linje.
- **Uændret:** nice, ionice, HF_HUB_OFFLINE efter download, slots (H007), H008-claim og H010-tilstande.

# Acceptkriterier
- AK1: Med en falsk motor, der returnerer segmenter og diarization-intervaller, får segmenterne korrekt taler efter
  overlap.
- AK2: Rollerne bliver korrekte: en taler med agentmarkør bliver Agent, og den anden Kunde. Uden markør bliver det
  Taler 1 og 2, efter rækkefølge.
- AK3: UI, .txt og MCP viser rollen. Transcripts uden taler vises uændret.
- AK4: Med `enabled = off` sendes ingen diarization-argumenter, og uddata er uændret.
- AK5: Fejler diarization, bliver transcriptet stadig gemt og markeret som færdigt.
- AK6: Smoke på DEV: tre nye opkald har Agent/Kunde, der giver mening, og loggen viser diar-tid. Ejeren vurderer.

# Out of scope
Mere end 2 roller (fx overdragelse til en tredje), stemmegenkendelse af navngivne agenter, GPU og re-transcription af
historik.

# Feature flag
Engineeren vælger mellem config og flag efter frameworkets regler og begrunder det i v0. Det skal kunne slås fra uden
deploy.

# Rollback
`[diarization] enabled = off` eller flag fra. Eller Revert-H.
